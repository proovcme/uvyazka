**Проверяемая память строительного проекта для РП и ГИПов.**

Увязка сохраняет документы, числа, их источники и результаты сопоставления
между диалогами. Модель работает в вашем ИИ-клиенте, а локальные MCP-инструменты
и навыки помогают читать проект, находить расхождения и готовить основания
для графика, ПОС и ППР.

[Быстрый старт](#быстрый-старт-на-windows) · [Скриншоты](#панель) ·
[Подключение](#подключение) · [Открыть 3D-демо](https://locia.work/uvyazka/) · [Документация](#документация)

Модель исследует проект и принимает решения в диалоге. Увязка помогает ей
работать быстрее и точнее: хранит результаты между сессиями, выдаёт адресные
фрагменты, выполняет воспроизводимые расчёты и сохраняет основания выводов.
Список готовых проверок дополняет самостоятельный анализ модели.

## От документа к проверяемому числу

| Задача | Что даёт Увязка |
|---|---|
| Продолжить работу с проектом | Локальную память с версиями и поиском по сохранённому тексту |
| Понять, откуда значение | Исходное написание, единицу, основание и адрес в документе |
| Сопоставить количества | Сравнение при одинаковом смысле и единицах, вопросы при расхождении |
| Исправить чтение | Новую ревизию с причиной, сохранением истории и пересмотром зависимостей |
| Вести несколько объектов | Отдельные базы и общий портфель проектов |

## Что уже работает в alpha

- Несколько проектов с отдельными SQLite-базами и общей локальной панелью.
- Чтение текстовых PDF, DOCX, XLSX/XLSM, CSV/TSV, UTF-8 TXT/MD.
- Текстовый поиск и источник до страницы, абзаца, строки или ячейки.
- Наблюдения с исходным написанием, единицами, смыслом и версией источника.
- Сверка сопоставимых количеств, история исправлений и зависимые проверки.
- Граф работ из данных PDF/DWG/таблиц или IFC, версии сценариев и выгрузка CSV.
- Ограничения ресурсов, проверка циклов, критический путь по связям, журнал и 3D.
- Приближённые объекты по заданным размерам; импорт IFC отдельной опцией.
- Общие помещения, оборудование и требования; сверка сведений между разделами,
  обязательных подключений и цепочек до источников, включая маршруты внутри щитов.
- Шесть навыков: чтение проекта, сверка, график, ПОС, ППР и влияние изменений.

Адресное OCR сканов через Tesseract, часы и ампер-часы, разделение расхождений,
вопросов и непроверенного объёма: [порядок работы](docs/OCR_AND_REVIEW.md).

**0.3.0-alpha.12:** 68 инструментов MCP и шесть навыков. Добавлена
[постоянная память измерений PDF](docs/MEASUREMENTS.md): отдельные виды и масштабы,
контуры, наложение на источник, история и пересчёт после исправления калибровки.
В локальной панели — рабочее место **«Лист и измерения»**: можно обводить
контуры вручную, видеть работу агента и продолжать её в той же базе проекта.
Модель интерпретирует чертёж; инструменты считают и сохраняют. RVT-системы читаются по
явным связям, с Unicode-названиями, ссылками цепей на базовое оборудование и
происхождением каждого участника. Перенесено обновление
IFCCS 0.5: длительности по объёмам и выработке, инженерные работы, стадии,
объединение моделей, создание IFC по описанию агента и анимация площадки.
Полное извлечение всех показателей, инженерные расчёты сетей
и автоматический выпуск ПОС/ППР ещё требуют развития.
[Статус реализации](docs/STATUS.md).

Из [Л.И.С.Т.](https://github.com/proovcme/les-list) перенесены функции чтения
структуры и таблиц: поиск экспликаций, характеристики вентиляции, водные
балансы, состав проекта и оглавления. Каталог сохраняется между сессиями;
исходные ячейки читаются с хешем, страницей и координатами.
[Четыре инструмента и границы переноса](docs/DOCUMENT_TABLES.md).

Публичное приложение открывается как **вьювер DWG / RVT / IFC**: дерево элементов,
этажи и свойства модели; отдельный режим «Симуляция». В alpha.8 холст занимает
высоту окна, боковые панели сворачиваются, а график раскрывается под моделью. DWG/DXF открываются
в отдельном локальном CAD-движке со слоями. Расчёт сценария доступен для IFC/RVT.
[Возможности и ограничения вьювера](docs/VIEWER.md).

Рабочие проходят проверяемый маршрут, выполняют действие у элемента и возвращаются.
Если доступ не найден, показывается причина блокировки. [Проверки анимации и ограничения](docs/SITE_ANIMATION.md).

**RVT → IFC без Revit.** Исходники конвертера и reader стадий теперь
[в составе репозитория](integrations/README.md). После локальной сборки
агент может импортировать RVT, получить IFC, проверить диагностику и
работать с моделью в том же наборе инструментов. Поддержка версий и геометрии
частичная. Параметры, виды и сохранённые спецификации читаются напрямую
без Revit и без конверсии в IFC, с кешем и источниками.
Для обработки модели целиком есть `prepare_rvt_model`: агент одним вызовом
запускает извлечение и проверенную IFC-конверсию, получает отчёт обоих этапов.
[Что извлекается и что пока нет](docs/RVT_DATA.md).
**[Открыть DWG / RVT / IFC в браузере](https://locia.work/uvyazka/).**
Конверсия, вьювер и расчёт IFCCS работают на устройстве пользователя.
В текущей локальной сборке для RVT/IFC сняты прежние пороги 64/128 MiB; размер зависит от памяти,
у RVT-читателя технический предел 2 GiB. DWG/DXF до 64 MiB.
Есть сохраняемый [журнал этапов, ошибок и предупреждений](docs/VIEWER.md#журнал-обработки).
Добавлен [каталог видов, листов и спецификаций RVT](docs/VIEWER.md#виды-листы-и-спецификации-в-локальной-смотрелке):
сохранённые поля и ячейки, связи листов, ориентация вида, кеш по SHA-256 и JSON/CSV.
Оформленные чертежи и вычисляемые строки спецификаций пока не восстанавливаются.
Файлы не отправляются на VPS. Публичное демо обновляется отдельно.
[Резервный адрес демо](https://proovcme.github.io/uvyazka/) содержит тот же
проверенный выпуск с моделями, свойствами и браузерными декодерами.
[Сборка и ограничения](docs/PUBLIC_DEMO.md) · [Прогоны 10 моделей](docs/BROWSER_VALIDATION.md).

## Быстрый старт на Windows

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```powershell
git clone https://github.com/proovcme/uvyazka.git
cd uvyazka
uv sync --extra all
uv run uvyazka demo
uv run uvyazka dashboard
```

Панель: http://127.0.0.1:8772. Два учебных проекта содержат синтетические
данные. Собственные документы и базы не включены в репозиторий.

## Подключение

Основной интерфейс — локальный MCP. Первая целевая среда — Codex на Windows,
далее Claude Desktop и другие совместимые клиенты. Навыки и установка
адаптируются к конкретному приложению; совместимость проверяется отдельно.

```powershell
uv run uvyazka client-config codex
```

Команда выводит фрагмент настроек текущей установки. Добавьте его в настройки
клиента, сохранив остальные серверы. Есть профили `claude-desktop` и
`gemini-cli`; совместимость с Gemini Desktop не заявляется.
Проверен stdio-протокол, установка в настольных клиентах требует отдельной приёмки.

Модель и диалог остаются в выбранном клиенте. Обязательного подключения
к API моделей или собственного сервера генерации у Увязки нет.
CAD/BIM, семантический поиск, RAG-Legion, независимая интеграция ЛЕС,
локальные модели и прямые API — дальнейшие дополнительные интеграции.
MCP-фрагменты передаются выбранному ИИ-клиенту и обрабатываются по его настройкам.

## Панель

**Веб-демо с данными.** [Открыть клинику](https://locia.work/uvyazka/): архитектура,
ОВ, ЭОМ и сводная модель; помещения, параметры и исходные количества доступны
в «Данные модели» с экспортом CSV/JSON. В верхнем выборе примеров есть RVT RE1,
который читает браузерный декодер. RVT поддерживается частично; результат и
пропуски видны в журнале. [Примеры, источники и ограничения](docs/PUBLIC_DEMO.md).

**Добавить проект.** Выберите существующую папку системной кнопкой или укажите
её путь — файлы читаются на месте. ZIP принимается отдельным импортом.
Модель может передать тот же путь через `import_project_folder`.
У обоих входов общие project_id, база и журнал; человек и модель продолжают
работу с одних данных. [Приём и продолжение](docs/PROJECT_INTAKE.md).

**Сводка после чтения.** Автоматика собирает числовые фрагменты с единицами
и ссылками на источники из сохранённого текста. Обзор показывает табличные ТЭП,
состав и покрытие, «Найденные данные» — поиск по кандидатам. Проверенные моделью
наблюдения хранятся отдельно; автоматические кандидаты не считаются принятыми
показателями или найденными ошибками. Те же данные доступны через MCP
`get_project_summary`. [Что извлекается и как продолжить](docs/PROJECT_SUMMARY.md).

**RVT без агента.** В локальной панели выберите «Загрузить RVT»:
чтение данных, конверсия в IFC и проверки запускаются автоматически.
Можно добавить условный сценарий работ и перейти в 3D/симуляцию.
Файл и расчёты остаются на этом компьютере; Revit не требуется.
[Процесс и ограничения](docs/RVT_DATA.md#загрузка-в-панели-без-агента).

![Загрузчик RVT на учебном проекте](docs/assets/rvt-upload.png)

а исходная строка открывается из карточки показателя.

## Принципы

- Каждое значение связано с источником и его версией.
- Пропуск, ошибка извлечения и проектное расхождение имеют разные статусы.
- Полноту извлечения нужно подтверждать по документам и строкам;
  полный журнал покрытия строк пока не реализован.
- Данные разных проектов разделяются; исходные документы сохраняются.
- Общая база проекта используется всеми клиентами и панелью.

## Проверка разработки

```powershell
uv sync --extra all
uv run python -m unittest discover -s tests -v
uv run python tools/validate_package.py
uv build
```

Все тестовые источники создаются синтетически во временных папках.
CI задан для Windows/Linux, Python 3.11/3.12.
