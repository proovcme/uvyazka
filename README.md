# Увязка · uvyazka

Набор MCP-инструментов и навыков для руководителей проектов и ГИПов.
Проверяемая база строительного проекта: показатели, сопоставление ПД и РД,
объёмы, сметы, ресурсы и планирование.

## Как используется

Пользователь работает в привычном настольном ИИ-клиенте. Клиент ведёт диалог
и использует свою модель; Увязка предоставляет локальные инструменты, данные
и инженерные процедуры. Основной сценарий не требует вызовов API моделей
со стороны Увязки, собственной LLM или отдельного чат-приложения.

Основной способ подключения — локальный MCP через stdio. Навыки и инструкции
адаптируются к возможностям конкретного клиента. Первая целевая среда — Codex
на Windows; далее Claude Desktop и другие совместимые клиенты. Поддержка
Gemini определяется конкретным клиентом и его механизмом инструментов:
наличие MCP в Gemini CLI не означает проверенной поддержки в настольном приложении.

## Что разрабатываем

- Приём ПД/РД, реестр документов, версии и кеш извлечения.
- Базу показателей: ТЭП, помещения, площади, этажность, высоты, ТУ, мощности,
  расходы, оборудование, материалы, количества и финансовые показатели.
- Сверку проект → спецификация → ВОР → смета → поставка с проверкой
  наименований, свойств, единиц, состава и границ работ.
- Источник каждого числа: документ, версия, страница/лист, строка/ячейка
  или объект CAD/BIM; статус извлечения и подтверждения.
- Перечень работ, зависимости, ресурсы и расчётный график, затем подготовку
  ПОС и ППР по проверенным исходным данным.
- Простую локальную панель для просмотра показателей и открытых вопросов.

Поиск помогает найти сведения. Полный обход документов и таблиц, проверка
покрытия, расчёты и хранение принятых фактов — отдельные процедуры.
Отсутствующее значение не равно нулю; совпадение OCR не равно подтверждению оригинала.

## Состав

| Компонент | Ответственность |
|---|---|
| Ядро | Проекты, источники, наблюдения, факты, расчёты, сверки и журнал изменений |
| MCP | Ограниченные инструменты чтения и контролируемого пополнения базы |
| Навыки | Порядок чтения, сопоставления, планирования и подготовки документов |
| Адаптеры клиентов | Подключение MCP и упаковка инструкций для конкретного приложения |
| Панель | Представление данных той же базы, с переходом к источникам |
| Дополнительные подключения | CAD/BIM, ЛЕС, векторный поиск, локальные модели и API |

SQLite — первоначальное структурированное хранилище. Текстовый поиск должен
работать без обязательного сервера моделей. Векторный поиск и OCR подключаются
по необходимости; схема базы и происхождение фактов от них не зависят.

## Переиспользование и интеграции

Из RAG-Legion отбираются пригодные решения чтения, кеширования, происхождения
и долгих заданий, с проверкой зависимостей и сохранением происхождения кода.
[ЛЕС](https://github.com/proovcme/LES) остаётся самостоятельным продуктом:
удачные общие решения изучаются отдельно, связь обеспечивается явными
контрактами интеграции. Увязка не требует запущенного ЛЕС или RAG-Legion.

Общая инженерная база принадлежит проекту, а не истории одного чата или клиента.
Смена клиента не должна требовать повторного чтения всего проекта.

## Состояние

Репозиторий инициализирован описанием продукта и архитектурными границами.
Универсальная установка, миграция локального исследовательского прототипа
и приёмка по клиентам ещё не выполнены. Рабочие данные реального здания
не являются частью стартового репозитория.

Подробности: [архитектура](docs/ARCHITECTURE.md),
[первые этапы](docs/ROADMAP.md).
