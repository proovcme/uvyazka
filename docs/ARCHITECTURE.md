# Архитектура первой версии

## Основной путь

```text
Настольный ИИ-клиент и его модель
          │
          ├── навыки и инструкции для задачи
          │
          └── локальный MCP (stdio)
                    │
              ядро Увязки
                    │
        ┌───────────┼────────────────┐
        │           │                │
   база проекта  чтение/кеш      расчёты и сверка
        │           │                │
        └───────────┼────────────────┘
                    │
        панель и выдача с источниками
```

Увязка сама не обязана отправлять запрос генеративной модели. Она выдаёт клиенту
ограниченный пакет данных, принимает структурированный результат, проверяет
его форму и основания и сохраняет версию. Решение модели не становится
инженерно подтверждённым только потому, что JSON прошёл проверку.

## Данные и экономия контекста

Каждый объект имеет устойчивый project_id, определённый состав источников и
свои записи. Набор документов и физический объект — разные сущности: объект
может объединять ПД, РД, изменения, сметы и поставки из нескольких наборов.

Порядок обработки: реестр → извлечение → наблюдения → сопоставление сущностей
→ нормализованные величины → проверки → решения → планирование/документы.
Кеш привязан к хешу содержимого, версии парсера, параметрам и схеме результата.
Новая версия источника не должна незаметно наследовать старое подтверждение.

История диалога, сводка и семантический индекс не заменяют числовую базу.
Начало новой сессии: паспорт, покрытие, открытые вопросы и адресное чтение.
Долгие задания хранят очередь и результаты в базе, независимо от окна контекста.

## Переносимость между клиентами

Общие контракты инструментов и данные едины. Установка и представление навыков
проверяются отдельно для каждого клиента. Один каталог SKILL.md не объявляется
автоматически совместимым со всеми приложениями.

Codex — первая целевая настольная среда. Claude Desktop — следующий профиль.
Gemini и прочие семейства поддерживаются через конкретные клиенты с проверенной
возможностью локальных инструментов. Gemini CLI не подменяет настольную приёмку.
Проверка подключения должна включать обнаружение инструментов, выбор проекта,
чтение источника, ограниченный пакет и продолжение задания после нового диалога.

Локальный транспорт MCP не равен вызову API модели. Поддержка локальных LLM,
прямых API и удалённого MCP может добавляться явно как дополнительные режимы.
Не вводить скрытое переключение на другую модель при ошибке.

## RAG-Legion и ЛЕС

RAG-Legion — источник пригодных реализаций: адаптеры форматов, кеш разбора,
пакетное чтение, происхождение, управление изменениями. Его конфигурация,
собственные модельные сервисы и Open WebUI не становятся обязательными частями.

В ЛЕС полезны идеи неизменяемого снимка таблицы, журнала строк с атомарными пакетами,
бюджета контекста, чтения родителей и ссылки на фактически переданный источник.
Наличие этих модулей в исходниках не доказывает готовности для другого клиента.
Переиспользование кода учитывает лицензию и происхождение; интеграция не требует
слияния интерфейсов или переписывания ЛЕС под Увязку.

Адаптеры обмениваются manifest, source_ref, revision/hash, текстом/строками/координатами
и статусом покрытия. Идентификаторы сторон сопоставляются явно. У каждого источника
один ответственный за извлечение и кеш; не запускать несколько полных разборов молча.

## Числа и исправления

Сохранять исходное написание, значение, единицу, базу измерения, режим, сущность,
свойства и место в источнике. Для денег — валюту, дату/уровень цен, НДС и состав.
Для площади — определение; для мощности — установленную/расчётную/разрешённую;
для количеств — объём в деле/работу/ресурс/закупку/повторное использование.

При конфликте сохранять обе стороны и вопрос. При ошибке извлечения сохранять
поправку с причиной и доказательством, пересматривать зависимые выводы. Сам исходный
проект и прежняя версия наблюдения остаются доступными.
