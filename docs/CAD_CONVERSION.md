# DWG/DXF без AutoCAD: внешний ODA File Converter

Необязательный маршрут выпуска производной CAD-копии. Основной прямой
читатель DWG остаётся LibreDWG/WASM; конвертер не запускается скрыто при чтении.
Автокад, его консольный модуль, облако и API языковой модели не используются.

## Установка и настройка

Установить ODA File Converter отдельно с
[официального сайта](https://www.opendesign.com/guestfiles/oda_file_converter).
Проверить происхождение и условия лицензии выбранного дистрибутива.
Бинарники ODA, установщик и шрифты не входят в Увязку и не распространяются
под её Apache-2.0. Автоматической загрузки или принятия лицензии инструментом нет.

Установить `ezdxf>=1.4,<2` либо extra `uvyazka[authoring]`, затем настроить
исполняемый файл локально, в той же папке состояния, которую использует MCP:

```text
uvyazka --home STATE configure-cad --executable "PATH/ODAFileConverter.exe" --version "VERSION"
uvyazka --home STATE cad-status
```

`version` — справочная метка установки. Реальная идентичность фиксируется
SHA-256 исполняемого файла, соседних DLL/TX и Windows platform-плагинов.
После замены компонентов проверить происхождение и повторить настройку.
Путь программы нельзя передать из документа или через MCP-запрос конверсии.
В Windows используется штатный платформенный модуль с сокрытием окна;
неподдерживаемый `offscreen` принудительно не включается. На других платформах
доступность консольного запуска зависит от установленного пакета и окружения.

## Инструменты MCP

| Инструмент | Действие |
|---|---|
| `cad_converter_status` | Читает настройку, наличие и целостность внешней установки; ничего не конвертирует |
| `convert_cad_document` | Один зарегистрированный `doc_id` в выбранном `project_id`, явный `request_id`, формат DWG/DXF и версия ACAD2018/ACAD2013 |
| `get_cad_conversion` | Возвращает `summary`, `validation` или `diagnostics` по сохранённому `conversion_id` |

Файл регистрируется штатным приёмом/сканированием проекта. Источник проверяется
по хешу и копируется в отдельный каталог операции. Конвертер получает фиксированный
список аргументов, один фильтр файла, без рекурсии и исправления исходника.
Результат, обратный DXF и отчёт сохраняются в состоянии проекта. Исходный документ
не заменяется. Таймаут и ошибка остаются сохранённым исходом; тот же `request_id`
не запускает повтор автоматически. Для исправленного запуска нужен новый ID.
Отчёт фиксирует версию ezdxf и хеш кода проверки; после изменения проверяющего
кода прежний результат остаётся в истории с `current_validation_matches=false`.

## Границы проверки

Для DXF → DWG конвертер повторно читает DWG и сохраняет проверочный DXF.
Независимый разбор через ezdxf сверяет поддержанные примитивы и координаты,
определения блоков и вставки, значения/положение атрибутов, текст и стили,
слои, листы, видовые экраны, масштабы и блокировку масштаба. Допуск координат
указан в отчёте в единицах исходного чертежа. Сравнение сохраняет handles;
при их неподдержанном изменении автоматическое подтверждение не выдаётся.

Нормализации записываются отдельно: внутренние имена пространств листов,
сжатие пропусков во внутренних номерах при том же порядке вкладок, добавленные
пустые/служебные слои, неиспользуемая точка выравнивания левого текста,
опциональные значения по умолчанию. Запасной индекс ACI может измениться
при неизменном явном RGB; это диагностируется. Переключение слоя или RGB
не считается такой нормализацией. Неизвестная сущность не получает статус
проверенной только по совпадению числа объектов.

- `converted_checked`: проверенные данные поддержанной области совпали;
  это не равенство всех байтов, не проверка инженерного решения и не печать PDF.
- `converted_needs_review`: файл получен, но обнаружено отличие/неподдержанный тип.
- `converted_unverified`: DWG → DXF прочитан, но эквивалентность исходному бинарному
  DWG не доказана. Успешный разбор не выдаётся за полную проверку.
- `failed`: результата, принятого инструментом, нет. Прочитать диагностику.

Ссылки на TTF/SHX проверяются как данные стиля; файлы шрифтов не встраиваются.
На другом компьютере шрифты надо установить отдельно. Xref, proxy-объекты,
специальные CAD-таблицы, произвольные расширения и сложная 3D-графика требуют
отдельной проверки. Колонки MTEXT, многострочные атрибуты и словари расширений
не получают автоматического подтверждения данным проверяющим кодом. Нужно
визуально сравнить листы независимым рендером и проверить
печать выбранным издателем PDF. ODA File Converter сам PDF не выпускает.

Публичные регрессии используют только синтетические чертежи. Реальный конвертер
можно включить в локальном тесте переменной `UVYAZKA_TEST_ODA` с путём к программе;
без неё тест не скачивает и не устанавливает ODA. Для рабочего проекта отчёт
остаётся локальным: он может содержать технические и конфиденциальные данные.
