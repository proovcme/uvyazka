# График и моделирование

В Увязку перенесены ядро симуляции, IFC-импорт и исходные эвристики
авторского IFCCS. Инструменты встроены в тот же MCP и базы объектов:
отдельный IFCCS-сервер не нужен. Источником работ может служить любой формат,
который умеет читать агент доступными инструментами.

## Действия агента

1. Прочитать construction_schema; выбрать проект и проверить источники.
2. Из PDF, таблицы или DWG получить размеры/объёмы/технологии и их основания.
   Для DWG использовать доступный CAD MCP. Увязка сама DWG не разбирает.
3. При необходимости сохранить условные объекты save_spatial_model: метры,
   явное начало координат, границы, geometry_basis, источники и допущения.
   Или импортировать зарегистрированный IFC через import_ifc_model.
4. Составить сценарий save_construction_scenario. Каждая работа содержит
   id/name, длительность или calculation, зависимости, ресурсы, target_ids
   и evidence с причиной. Длительность по выработке считает
   calculate_work_duration: ceil(60 × объём / часовая выработка команды).
5. Рассчитать run_construction_scenario, проверить get_construction_run
   по страницам schedule/events. Сравнить варианты resource_overrides,
   не меняя сохранённую ревизию. Открыть «График и модель» в панели.

Само извлечение графа из полного комплекта выполняет модель. Автоматического
PDF/DWG→готовая BIM-модель здесь нет. Коробки — средство пространственного
представления гипотезы, с явной точностью и основанием.

## Расчёт

Целые непрерывные виртуальные минуты; FS без лагов. Ядро проверяет DAG,
существование зависимостей и ресурсов, возможность удовлетворить требования,
затем распределяет возобновляемые ресурсы по приоритету. Вычисляет начала,
окончания, ожидания, события и снимки для воспроизведения.

CPM и резервы считаются отдельно только по связям, без ресурсов. Приоритетное
распределение не доказывает глобально минимальный срок. Календари, смены,
погода, поставки, деньги, пространственная совместимость фронтов и вероятности
не реализованы как ограничения движка. Их нужно явно исследовать и, где
уместно, представить дополнительными работами/зависимостями; это не полноценная
замена специализированным моделям. Виртуальный срок не равен календарной дате.

suggest_ifc_scenario переносит исходные IFCCS-шаблоны по классам/материалам IFC.
Технологии и псевдослучайные воспроизводимые длительности там условные.
Результат — исходная гипотеза для пересборки по проекту, не готовый ПОС/ППР.

## Хранение и воспроизводимость

SQLite объекта содержит construction_models, construction_scenarios,
construction_runs, construction_requests. Геометрия — в каталоге состояния
объекта, вне репозитория. Ревизии сценариев и результаты запусков сохраняются.
Идентичный request_id с прежним содержимым повторяет результат, с другим
отклоняется. Изменение сценария требует expected_revision.

Ссылки могут указывать на блок документа с хешем и версией читателя,
зарегистрированный бинарный файл с locator или ревизию наблюдения fact_id.
При записи/запуске проверяется содержимое источников; это проверка версии,
а не доказательство правильности интерпретации данных.

Ограничения: 2000 работ, 100 ресурсов, 5000 условных коробок, до 200 строк
в ответе MCP; модель IFC до 100 MiB. Импорт/расчёт синхронные, длительный
импорт может потребовать увеличенного времени ожидания клиента.
Браузер получает полный пакет выбранной модели/запуска, MCP выдаёт страницы.

## Просмотр и выгрузка

Локальный read-only интерфейс `/simulation/?project=...` показывает модель,
Гант, ход работ, занятость ресурсов, основания и допущения. Скорость просмотра
не влияет на расчёт; перемотка воспроизводит сохранённый результат.
Параллельные операции над элементом должны завершиться все, чтобы элемент
показывался завершённым. Есть JSON журнала и CSV графика; CSV экранирует
входные строки, похожие на формулы. Исходные проектные файлы не изменяются.
