# График и моделирование

В Увязку перенесены ядро симуляции, IFC-импорт и исходные эвристики
авторского IFCCS. Инструменты встроены в тот же MCP и базы объектов:
отдельный IFCCS-сервер не нужен. Источником работ может служить любой формат,
который умеет читать агент доступными инструментами.

## Действия агента

1. Прочитать construction_schema; выбрать проект и проверить источники.
2. Из PDF, таблицы или DWG получить размеры/объёмы/технологии и их основания.
   DWG просматривается напрямую через LibreDWG в CAD-приложении. Перенос его
   объектов в общую базу/MCP пока не реализован; не считать просмотр извлечением.
   Следовать [маршруту прямого чтения](DIRECT_FILE_READING.md).
3. При необходимости сохранить условные объекты save_spatial_model: метры,
   явное начало координат, границы, geometry_basis, источники и допущения.
   Или импортировать зарегистрированный IFC через import_ifc_model.
4. Составить сценарий save_construction_scenario. Каждая работа содержит
   id/name, длительность или calculation, зависимости, ресурсы, target_ids
   и evidence с причиной. Длительность по выработке считает
   calculate_work_duration: ceil(60 × объём / часовая выработка команды).
5. Рассчитать run_construction_scenario, проверить get_construction_run
   по страницам schedule/events. Сравнить варианты resource_overrides,
   не меняя сохранённую ревизию. Открыть «График и модель» в панели.

Само извлечение графа из полного комплекта выполняет модель. Автоматического
PDF/DWG→готовая BIM-модель здесь нет. Коробки — средство пространственного
представления гипотезы, с явной точностью и основанием.

## Расчёт

Целые непрерывные виртуальные минуты; FS без лагов. Ядро проверяет DAG,
существование зависимостей и ресурсов, возможность удовлетворить требования,
затем распределяет возобновляемые ресурсы по приоритету. Вычисляет начала,
окончания, ожидания, события и снимки для воспроизведения.

CPM и резервы считаются отдельно только по связям, без ресурсов. Приоритетное
распределение не доказывает глобально минимальный срок. Календари, смены,
погода, поставки, деньги, пространственная совместимость фронтов и вероятности
не реализованы как ограничения движка. Их нужно явно исследовать и, где
уместно, представить дополнительными работами/зависимостями; это не полноценная
замена специализированным моделям. Виртуальный срок не равен календарной дате.

suggest_ifc_scenario использует IFCCS 0.5: классы, материалы, измеренные объёмы
и явно заданную выработку. Длительности рассчитываются, случайных минут нет.
Выработку можно передать через production; источник и достоверность каждого
объёма сохраняются. Неизвестный объём не заменяется нулём или объёмом оболочки.
Есть предварительные пакеты инженерных работ, нулевого цикла и средств доступа.
Выдержка бетона по умолчанию 28 суток — явное изменяемое допущение,
а не расчёт прочности. Условная приёмка не означает проведённого испытания.
Результат — исходная гипотеза для пересборки по проекту, не готовый ПОС/ППР.

## Модель из чертежей и объединение разделов

Дополнение `authoring` устанавливается отдельно: `uv sync --extra all --extra authoring`.
Агент читает `ifc_authoring_schema`, создаёт `create_drawing_model` внутри
выбранного project_id и присоединяет зарегистрированные документы через
`register_model_drawing`. Ответ содержит отдельный drawing_id и source.id.
`inspect_model_drawing` читает текст/вектор PDF, DXF или метаданные изображения;
`render_model_drawing` показывает страницу агенту. OCR и встроенной модели нет.
Структурированное чтение DWG этим инструментом пока не реализовано.
Установленный AutoCAD не является обязательным обходным путём.
Масштаб, начало координат и направление осей
агент задаёт явно, каждое решение связывает с источником и допущениями.

Агент сохраняет полное типизированное описание `save_ifc_model_spec`, затем
`build_drawing_model` создаёт IFC4 и проверяет повторное открытие, EXPRESS
и геометрию. Это проверка файла, правильность прочтения чертежа она не доказывает.
Геометрия попадает в существующий просмотрщик объекта. `render_spatial_model`
также возвращает PNG без браузера. `get_drawing_model` читает ревизию и элементы.

`federate_spatial_models` объединяет до 32 моделей одного проекта. Участник:
model_id, уникальный instance_id, необязательные label, offset_m=[x,y,z],
rotation_deg вокруг Z. Общие координаты проверяет агент; совпадение марок
не объединяет элементы автоматически. Исходные модели сохраняются отдельно.
Метаданные Revit позволяют явно выбрать исходное, новое и демонтируемое состояние
через phase_selections; отсутствие метаданных не восстанавливает их по догадке.

`import_rvt_model` — экспериментальный путь через rvt-rs. Исходники
конвертера и reader стадий включены в репозиторий; соберите их командой
`uv run python tools/setup_rvt.py`. Нужны Rust >=1.87 и системные build tools,
Revit не нужен. `rvt_converter_status` показывает наличие и целостность
бинарников. После импорта `get_rvt_conversion` выдаёт пути полученного IFC,
диагностику пропусков, выполненных исправлений и проверки схемы.
Качество преобразования и фазы нужно проверять на конкретном RVT.
Из грубой коробки нельзя получать рабочие объёмы. Подробности —
[сборка RVT](../integrations/README.md), [план браузерного демо](BROWSER_SIMULATION_PLAN.md).

## Хранение и воспроизводимость

SQLite объекта содержит construction_models, construction_scenarios,
construction_runs, construction_requests. Геометрия — в каталоге состояния
объекта, вне репозитория. Ревизии сценариев и результаты запусков сохраняются.
Идентичный request_id с прежним содержимым повторяет результат, с другим
отклоняется. Изменение сценария требует expected_revision.

Ссылки могут указывать на блок документа с хешем и версией читателя,
зарегистрированный бинарный файл с locator или ревизию наблюдения fact_id.
При записи/запуске проверяется содержимое источников; это проверка версии,
а не доказательство правильности интерпретации данных.

Ограничения: 2000 работ, 100 ресурсов, 5000 условных коробок, до 200 строк
в ответе MCP; модель IFC до 100 MiB, источник чертежа до 50 MiB,
экспериментальный RVT до 512 MiB. Импорт/расчёт синхронные, длительный
импорт может потребовать увеличенного времени ожидания клиента.
Браузер получает полный пакет выбранной модели/запуска, MCP выдаёт страницы.

## Просмотр и выгрузка

Локальный read-only интерфейс `/simulation/?project=...` показывает модель,
Гант, ход работ, занятость ресурсов, основания и допущения. Скорость просмотра
не влияет на расчёт; перемотка воспроизводит сохранённый результат.
Параллельные операции над элементом должны завершиться все, чтобы элемент
показывался завершённым. Есть JSON журнала и CSV графика; CSV экранирует
входные строки, похожие на формулы. Исходные проектные файлы не изменяются.

Вьювер показывает площадку с техникой, лесами и вышками по журналу расчёта;
это условная визуализация, не проект размещения техники. Сцены и «Автопоказ»
помогают осмотреть работы, включая длинные ожидания; сам расчёт они не меняют.
Доступны разрез и отдельные цвета моделей сводки.
[Публичное демо](https://locia.work/uvyazka/) включает открытые модели клиники,
пример RVT и отдельный синтетический сценарий; технологии расчёта требуют проверки.
[Сборка статического демо](PUBLIC_DEMO.md).
