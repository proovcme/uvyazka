# Данные и MCP

База каждого проекта хранится в `projects/<project_id>/project.sqlite3`
внутри каталога состояния. Общий реестр содержит регистрацию объектов.
Каждый запрос к данным объекта требует явного `project_id`.

| Инструмент | Назначение |
|---|---|
| `list_projects` | Выбор зарегистрированного объекта |
| `project_status` | Состав, покрытие и ограничения |
| `find_documents` | Поиск по имени, DOC-ID, хеши, статусы, продолжение |
| `search_project` | Ограниченный поиск по тексту и DOC-ID |
| `read_evidence` | Блок с локатором, версией читателя и продолжением |
| `get_project_facts` | Записанные наблюдения и свежесть источников |
| `get_reconciliation` | Сохранённые сопоставления и вопросы |
| `get_evidence_chain` | Наблюдение, история и зависимые сопоставления |
| `record_observations` | Запись пакета наблюдений с источниками |
| `compare_facts` | Десятичное сравнение двух наблюдений |
| `list_technology_sources` | Поиск метаданных трёх карточек ТТК |

`record_observations` и `compare_facts` изменяют базу. Остальные инструменты из этой таблицы
читают её. Ни один инструмент не изменяет исходные проектные документы.
Приём файлов и регистрация папок выполняются явно через CLI.

## Наблюдения

Пакет `record_observations` содержит `project_id`, уникальный `request_id`
и 1–40 элементов `observations`. Каждый элемент:

```json
{
  "id": "area-observation",
  "name": "Площадь участка",
  "group": "tep",
  "value": "12",
  "raw_value": "12 м2",
  "unit": "m2",
  "basis": "site_boundary",
  "entity": "site",
  "property": "area",
  "revision_set": "set-1",
  "sources": [{
    "doc_id": "ID_FROM_FIND_DOCUMENTS",
    "sha256": "HASH_FROM_READ_EVIDENCE",
    "parser_revision": "REVISION_FROM_READ_EVIDENCE",
    "page_number": 2
  }]
}
```

Это пример формы: идентификаторы и хеш нужно получить из источника проекта.
`raw_value` должно буквально встречаться в каждом указанном блоке.
Запись получает `source_observation`, `revision_approved=false`.
Проверка выдержки не доказывает правильность нормализации, смысла и единицы.

Группы панели: `tep`, `rooms`, `capacity`, `quantities`, `finance`,
`organization`. Обязательны name, group, value, raw_value, unit, basis, sources.
Для сопоставления нужны entity, property, revision_set; specification
должна совпадать, если она задана. Отсутствующее значение — null.
Специальные финансовые расчёты пока не реализованы: валюту, дату, НДС и
уровень цен следует сохранять явно; сравнение произвольных сумм не поддержано.

Повтор `request_id` с тем же пакетом возвращает прежний результат;
с другим содержимым отклоняется. Пакет записывается одной транзакцией.
Для исправления используйте тот же id, `expected_revision` и
`correction_reason`. Предыдущая ревизия сохраняется, зависимые проверки
получают `needs_review`.

## Сравнение

`compare_facts` принимает first_id, second_id, tolerance (строкой, по
умолчанию «0»). Допуск задаётся в базовой единице размерности: м³, м², кг и т. п.
Сначала проверяются сущность, свойство, база измерения, набор ревизий и
спецификация. Затем сравниваются величины.

Поддержаны известные единицы длины, площади, объёма, массы, количества,
мощности и расхода. Неизвестная единица или отсутствие числа дают
`not_comparable`; расхождение величин или смыслов — `question`.
Отрицательный допуск, NaN, бесконечность и чрезмерные числа отклоняются.
`matches` означает арифметическое совпадение записанных сопоставимых
наблюдений, а не инженерное утверждение проекта.

## Источники и свежесть

Идентичность блока: проект + doc_id + sha256 + parser_revision + page_number.
В PDF page_number — порядковый номер страницы от 1, не номер листа чертежа.
Для Office/текста это номер извлечённого блока; фактический адрес находится
в `locator`: лист/ячейки, таблица/строка, абзац или строка.

`read_evidence` ограничивает выдачу; `next_offset` продолжает блок.
Передавайте хеш и версию читателя для воспроизводимого чтения.
Старый извлечённый текст сохраняется, оригинал старой версии не архивируется.

`snapshot_metadata_matches` означает совпадение размера и времени файла.
`content_hash_matches` — проверку полного хеша в конкретной операции.
`historical_snapshot`, `stale_version`, `needs_refresh`, `source_unavailable`
требуют внимания. Ни один статус не утверждает действующую ревизию.
Повторный `scan` обновляет активный поисковый индекс.
