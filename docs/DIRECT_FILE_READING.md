# Прямое чтение RVT и DWG

Принято 2026-10-21: основной маршрут Увязки — чтение файлов локальными
декодерами, включая WASM в браузере. Установленные Revit/AutoCAD,
агент внутри CAD/BIM и облачная конверсия не являются зависимостями этого
маршрута. MCP предоставляет инструменты клиентской модели и доступ к памяти
проекта; собственный чат или API языковой модели для извлечения не нужны.

## Что уже есть

| Формат | Реализованный путь | Граница |
|---|---|---|
| RVT | rvt-rs, локальный metadata-reader и браузерный WASM-мост; кеш нативных записей в SQLite через extract_rvt_data | Частичное чтение; поддержка зависит от версии и класса. Настройки видов не равны изображению, сохранённые ячейки не равны вычисленной спецификации |
| DWG | LibreDWG через самостоятельное CAD-приложение MLightCAD в браузере | Просмотр частичный. Структурированный перенос объектов из этого приложения в общую базу и MCP пока не реализован |
| DXF | ezdxf для примитивов в локальных инструментах, CAD-приложение для просмотра | Существующее чтение примитивов не является полным каталогом блоков, таблиц, листов и внешних ссылок |
| IFC | web-ifc в браузере, IfcOpenShell в локальных инструментах | Доступны данные самого IFC; свойства, потерянные при его экспорте, не восстанавливаются автоматически |

Возможности Autodesk API не являются обещанием возможностей прямого декодера.
Проверять установленную сборку, а не переносить поддержку из свежего upstream
на рабочую версию. Успех загрузки, число слоёв и экспортируемое тело не доказывают
полноту проекта. Тело из bbox считать только габаритным представлением.

## Следующая работа — ещё не реализовано

Приоритет пользователя — RVT. Сначала развивать параметры элементов,
помещения и оборудование, виды, спецификации и явные связи систем.
Для адресного поиска уже сохранённых параметров добавлен
`find_rvt_parameters` ([контракт](RVT_DATA.md#поиск-параметров-в-снимке));
это не расширяет возможности бинарного декодирования. DWG остаётся
вторым направлением. Список ниже описывает задачи по обоим форматам.

1. Для DWG вывести структурированные записи из существующего прямого
   декодера: идентификаторы, типы объектов, слои, блоки, атрибуты и тексты.
   Сохранить определения блоков отдельно от вставок и их трансформаций;
   не терять происхождение при раскрытии вложенных блоков.
2. Сохранять и адресно читать эти записи в общей базе проекта через MCP.
   Вьювер должен обращаться к тому же снимку; отдельная память чата не нужна.
3. Добавлять листы, видовые экраны и их масштабы, таблицы и внешние ссылки
   по мере подтверждения декодирования. Неразрешённая ссылка — пробел покрытия,
   а не пустой чертёж. Чертёж из линий и текстов не объявлять таблицей без
   отдельного разбора и доказательств.
4. Для RVT обновлять и расширять прямой декодер с сохранением локальных
   исправлений. Раздельно проверять элементы, параметры, определения видов,
   спецификации, геометрию и инженерные связи. Расширение одной подсистемы
   не означает поддержку остальных.
5. Дать модели средства сопоставления оборудования, таблиц и выпусков.
   Извлечение записей и арифметика выполняются кодом; назначение, соответствие
   объектов и инженерные выводы формирует модель с основаниями.

## Контракт сохраняемых данных

Каждый снимок должен иметь project_id, doc_id, SHA-256 исходника, версию/хеш
декодера и параметры извлечения. Утверждённую ревизию хранить отдельно от хеша.
Повторное чтение того же источника той же сборкой использует кеш; изменение
исходника или декодера создаёт новый снимок, не стирая прежнее основание.

Для записи сохранять исходный ID/handle и его область: документ, блок,
вставка или связанный файл; класс/тип, исходное значение, единицы и адрес поля.
Нормализованные значения и связи хранить отдельно с методом получения.
Не назначать единицы, систему или назначение по догадке внутри декодера.

Покрытие отражать отдельно для чтения контейнера, записей, свойств, геометрии,
видов, таблиц и связей. Если знаменатель неизвестен, полнота неизвестна.
Различать «прочитано пустое», «не поддерживается», «ошибка» и «не проверялось».
Нулевой список из неработающего декодера не означает отсутствие объектов.

Связность по явным ссылкам, пространственное совпадение и инженерная
достаточность — разные утверждения. Размерная надпись не подтверждает
геометрический размер; площадь/объём bbox не являются количеством материала.

## Лицензии и проверка

Сохранять происхождение и лицензии декодеров. CAD-приложение с LibreDWG
распространяется отдельно по GPL-3.0-or-later; изменения его кода и доступность
соответствующих исходников учитывать при публикации. Не переносить его код
в другие компоненты без проверки условий. Подробнее: [вьювер](VIEWER.md).

Публичные регрессии — на синтетических или разрешённых образцах. Частные
модели, снимки и выгрузки остаются локальными. Отчёт должен отличать проверку
кода от проверки на реальном файле и от сравнения с эталоном.
