# Инструменты рядом с Увязкой

Модель работает в Codex, Claude Desktop, Gemini CLI или другом клиенте.
Она может обращаться к нескольким MCP в одном рабочем процессе.
Ни один из перечисленных проектов не требуется для запуска ядра Увязки.

| Проект | Роль | Связь сейчас |
|---|---|---|
| [RU AEC Skills](https://github.com/proovcme/ru-aec-skills) | Инженерные навыки и порядок работы по дисциплинам | Дополнительные инструкции агента; устанавливаются отдельно |
| [ЛЕС](https://github.com/proovcme/LES) | Самостоятельная система работы с документами и MCP | Можно подключить рядом; прямой адаптер обмена базами пока не реализован |
| [Л.И.С.Т.](https://github.com/proovcme/les-list) | Отдельно опубликованный читатель структуры ПД/РД и таблиц | Код и тесты изучены; [контракт будущего адаптера](LES_LIST_REVIEW.md), интеграция пока не включена |
| [ФГИС ЦС MCP](https://github.com/proovcme/fgis-mcp) | Доступ к официальным данным ФГИС ЦС с доказательствами | Отдельный источник для сметных задач; автоматического расчёта сметы в Увязке нет |
| [BIMwright](https://github.com/bimwright) | Семейство MCP для нативных CAD/BIM-приложений | Внешние инструменты агента; не код и не продукт автора Увязки |

Практический маршрут: агент читает документы через Увязку/ЛЕС, получает
нативные объекты CAD/BIM доступным коннектором, сохраняет соответствия и
основания в Увязке, выполняет проверку/расчёт и возвращается к исходному
документу. Наличие нескольких MCP ещё не обеспечивает единые идентификаторы:
project_id, ревизию, файл/хеш и адрес объекта нужно передавать явно.

RAG-Legion изучен как источник архитектурных идей. Его код и адаптер в
текущую версию не включены. Возможное переиспользование оценивается
покомпонентно по совместимости и лицензиям; локальная модель не должна
становиться обязательной для Увязки.
