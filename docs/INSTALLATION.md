# Установка и подключение

Нужны Python 3.11+ и, для приведённых команд, [uv](https://docs.astral.sh/uv/).
Команды ниже выполняются в PowerShell. Используйте постоянную папку установки:
конфигурация MCP будет ссылаться на Python внутри неё.

```powershell
git clone https://github.com/proovcme/uvyazka.git
cd uvyazka
uv sync --extra all
uv run uvyazka demo
uv run uvyazka dashboard
```

Откройте http://127.0.0.1:8772. Два учебных объекта созданы из синтетических
текстов и таблиц. Повторная команда `demo` сохраняет существующие источники.
Панель показывает сохранённые наблюдения, вопросы и ссылки на исходные блоки.
Она не извлекает все показатели автоматически.

Без uv: создайте виртуальное окружение через `python -m venv .venv`,
активируйте его и выполните `python -m pip install '.[all]'`.
Далее используйте `uvyazka` вместо `uv run uvyazka`.

## Где хранятся данные

По умолчанию Windows использует `%LOCALAPPDATA%\uvyazka`, другие ОС —
`~/.local/share/uvyazka`. Путь можно задать переменной `UVYAZKA_HOME` или
глобальным аргументом `--home`, расположенным перед командой.
Во всех клиентах и панели указывайте одинаковый путь.

```powershell
uv run uvyazka --home C:\ProjectMemory add-project object-a C:\Projects\Object-A --name "Объект А"
uv run uvyazka --home C:\ProjectMemory scan object-a --limit 100
uv run uvyazka --home C:\ProjectMemory status object-a
uv run uvyazka --home C:\ProjectMemory dashboard
```

Папка состояния должна находиться вне папки исходников. Регистрируйте точную
папку объекта: сканирование обходит её рекурсивно. Скрытые папки, ссылки,
кеши и служебные каталоги исключаются. Предварительно отделите результаты
анализа от исходного комплекта. Исходные файлы открываются для чтения.

`scan` регистрирует состав и обрабатывает ограниченное число ожидающих файлов.
Повторите команду при `remaining_in_batch > 0`. Неизменённый извлечённый текст
повторно не разбирается; хеши поддерживаемых файлов проверяются при сканировании.
Это ручной запуск: слежения за папкой в этой версии нет.

## MCP в клиенте

Команда создаёт фрагмент настроек с абсолютными путями текущей установки.
Она выводит текст и не меняет настройки приложений.

```powershell
uv run uvyazka client-config codex
uv run uvyazka client-config claude-desktop
uv run uvyazka client-config gemini-cli
```

Добавьте выведенный блок в конфигурацию выбранного клиента, сохранив остальные
серверы и настройки. Для отдельной базы добавьте `--home` перед `client-config`.
Перезапустите MCP в клиенте и начните с `list_projects`, затем
`project_status(project_id=...)`.

Профили рассчитаны на Codex, Claude Desktop и Gemini CLI.
Наличие профиля не означает проверку установки в соответствующем приложении.
Для Gemini Desktop совместимость не заявляется. Проверки выполнены официальным
MCP-клиентом по stdio; клиентская авторизация и интерфейс проверяются отдельно.

`plugin.json`, `mcp.json` и каталог `skills/` образуют переносимый пакет
исходников. Его запуск через manifest требует uv в PATH; обычная ручная MCP-настройка
использует Python установленного окружения. Подключение через каталог плагинов
конкретного приложения не проверено. Для читателей PDF/Office установите extra `all`.

## Навыки

```powershell
uv run uvyazka export-skills C:\AgentSkills\uvyazka
```

Команда экспортирует шесть навыков и их справочные материалы, в том числе из
установленного wheel. Другие версии файлов не перезаписываются.
Затем подключите навыки штатным способом вашего клиента. Автоматическая
установка в глобальные каталоги клиентов не выполняется.

## Что получает модель

Ядро не отправляет данные в API моделей. Возвращённые MCP-фрагменты попадают
в контекст выбранного вами ИИ-клиента и обрабатываются согласно его настройкам.
Локальное хранение базы само по себе не означает локальную обработку моделью.
Сервер использует права пользователя ОС; регистрируйте только доступные
данному клиенту проекты. Разграничения доступа между пользователями здесь нет.

Панель доступна на loopback, предназначена для локального чтения и не имеет
сетевой авторизации. Не публикуйте её порт во внешнюю сеть.

## Планирование и IFC

В demo у объекта А есть условная модель, два расчёта графика и вопросы
по связям разделов. В объекте Б этих данных нет: их создаёт агент через MCP.
В панели откройте «График и модель» или `/simulation/?project=demo-a`.
Расчёт и геометрические коробки не требуют Node.js или IFC-библиотек.

Для импорта настоящего IFC: `uv sync --extra all --extra ifc`.
Зарегистрируйте папку и выполните scan, затем передайте doc_id IFC
инструменту import_ifc_model. Статус текстового читателя unsupported для IFC
не мешает отдельному импорту геометрии. Предельный размер IFC — 100 MiB.

Для изменения интерфейса 3D нужен Node.js 22.12+:
в каталоге web выполните `npm ci`, `npm test`, `npm run build`.
Собранные ресурсы включены в Python-пакет и работают без CDN.

Для создания IFC по описанию агента, чтения DXF и рендера:
`uv sync --extra all --extra authoring`. Порядок действий и границы
экспериментального RVT описаны в [CONSTRUCTION.md](CONSTRUCTION.md).

Для RVT из checkout Увязки: `uv run python tools/setup_rvt.py`, затем
`uv run uvyazka rvt-status`. Скрипт использует включённые исходники и
Cargo.lock; Rust >=1.87 и системные C/C++ build tools должны быть установлены.
Если для MCP задан UVYAZKA_HOME, используйте его и при сборке (или --home).
Бинарники устанавливаются в состояние пользователя, исходный RVT сохраняется.

Для внешней установки можно явно задать UVYAZKA_RVT_BIN_DIR или отдельные
UVYAZKA_RVT_IFC / UVYAZKA_RVT_INFO / UVYAZKA_RVT_METADATA. Старое
IFCCS_RVT_IFC также поддерживается. Для таких overrides происхождение
бинарников не считается проверенным по включённому снимку исходников.

После подготовки runtime и extra authoring перезапустите локальную панель.
В разделе «Загрузить RVT» можно выбрать файл без агента: приложение запустит
извлечение, конверсию и, по выбранной опции, условную симуляцию. Настройки
UVYAZKA_HOME должны совпадать у сборки, панели и MCP.
[Порядок и пределы загрузки](RVT_DATA.md#загрузка-в-панели-без-агента).
