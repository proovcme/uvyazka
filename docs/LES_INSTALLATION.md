# Первая установка по команде LES

Контракт `uvyazka.install.v1` предназначен для явного действия пользователя
«Установить Увязку» в LES или другом локальном клиенте. Это первая установка
Windows x64 для текущего пользователя, без обязательных Python, Node.js и Rust.
Программа и проектные базы хранятся отдельно. Модели и OCR-веса не скачиваются.
WebView2 при необходимости получает штатный NSIS-установщик.

## Файлы выпуска

Новые совместимые GitHub Releases содержат:

- `uvyazka-install.json`: версия, платформа, SHA-256 и размер установщика,
  URL той же версии, режим `currentUser`, фиксированный аргумент `/S`;
- `install-windows.ps1`: команда для первой установки;
- `uvyazka_<version>_x64-setup.exe` и его `.sig` для штатного updater;
- соответствующие исходники приложения и зависимостей.

У старых выпусков этих файлов может не быть. Отсутствующий манифест означает
«эта версия не поддерживает установку из LES», а не повод угадывать имя EXE.
Предварительную версию клиент предлагает явно; перехода на beta без выбора нет.

Сборка по тегу создаёт **черновик** GitHub Release. Он не доступен обычному
пользователю до публикации. Тег обязан совпадать с версией установщика.
Опубликованный выпуск workflow не перезаписывает. Локальный запуск workflow
без тега сохраняет артефакт сборки и не публикует выпуск.

## Команда клиента

Клиент выбирает опубликованную версию, получает манифест только из
`https://github.com/proovcme/uvyazka/releases/download/v<version>/uvyazka-install.json`
и проверяет схему, версию, платформу и официальный адрес. Скрипт скачивается
из этого же выпуска и сверяется с `bootstrap.sha256` **до выполнения**.
Рекомендуется поставлять проверенный скрипт в самом клиенте; исполнение
произвольного текста из сети через `Invoke-Expression` не требуется.

```powershell
# Скрипт заранее получен и проверен клиентом. Пример версии синтетический.
powershell.exe -NoProfile -File .\install-windows.ps1 -Version 1.2.3 -Install
```

Без `-Install` и `-VerifyOnly` выполняется только проверка манифеста и вывод
плана. `-VerifyOnly` дополнительно загружает и проверяет байты, но не запускает
EXE. Политика исполнения PowerShell и проверки Windows не отключаются. Если
организация запрещает скрипты, клиент может реализовать этот же контракт
нативно или предложить обычный установщик.

Скрипт разрешает только HTTPS GitHub Releases этого репозитория и официальные
хосты выдачи release-assets. Есть пределы размера, времени ожидания, числа
перенаправлений и запрет параллельных установок. Аргументы из манифеста
не становятся произвольной командой: допускается только `/S`. Загрузка
и проверка предшествуют запуску. Повторная проверка наличия установленной
программы выполняется перед запуском EXE. Процессы и рабочие проекты не убиваются.

Проверка bootstrap: SHA-256 из официального манифеста, полученного по HTTPS.
Она **не является** проверкой Ed25519 или Windows Authenticode. `.sig` сохраняется
для штатного Tauri updater, который проверяет её своим закреплённым ключом.
Это разные границы доверия; клиент с собственным верификатором может проверить
`.sig` перед первой установкой дополнительно. Закрытые ключи в контракт не входят.

## Результат и повторный запуск

Stdout — строки JSON `uvyazka.install-event.v1`: `checking`, `plan`,
`downloading` с полученными/полными байтами, `verified`, `installing`,
`installer_finished`, `existing_installation`, `error`, `cleanup_pending`.
Неизвестный полный размер может быть null. Код завершения: 0 — операция
завершена, 1 — ошибка, 3 — найденная установка требует штатного обновления.
`reboot_required` сообщает код 3010, автоматической перезагрузки нет.

`installer_finished` с `service_ready=false` не означает, что API уже работает.
LES должен запустить/обнаружить Увязку и повторить проверку соединения,
возможностей вьювера и API. В окно установки возвращаются причина и следующий
шаг, а не выдуманная готовность. Автозапуск после установки не включён в скрипт.

Если Увязка уже установлена или работает, bootstrap отказывается заменять её.
Используется кнопка обновления Увязки: она проверяет активные задания, делает
резервные копии SQLite и проверяет подпись. Проверка наличия по реестру и
процессам не заменяет окончательное обнаружение API клиентом.

Собственные временные загрузки удаляются после завершения. Если установщик
продолжает работать после предельного ожидания, файлы сохраняются, выводится
ошибка; процесс принудительно не завершается. Невозможность очистки выводится
отдельным событием. Никакие пользовательские папки не чистятся.

## Границы приёмки

Синтетические тесты выполняют настоящий координатор с подменёнными сетью
и запуском EXE: порча байтов, другая версия/URL/платформа, лишние аргументы,
существующая установка, её появление во время загрузки, ошибка установщика
и очистка временных файлов. Они не устанавливают программу и не доказывают
первую установку на чистой Windows. Для выпуска нужны подписанная сборка,
приёмка отдельной установки и публикация черновика. Подключение команды
к кнопке LES — отдельная сторона того же контракта.

Основа: [режимы NSIS Tauri](https://v2.tauri.app/distribute/windows-installer/),
[подпись штатных обновлений](https://v2.tauri.app/plugin/updater/).
