# Открытие источника из LES

Кандидат интеграции, рабочая установка не переключается автоматически.
LES импортирует неизменяемый снимок `UvyazkaModelData` через локальные
`/api/models/datasets`, `/api/models/query`, `/api/models/object`. Чтение исходника
и снимок создаются в Увязке. LES не копирует CAD/BIM-декодеры и не меняет оригинал.

Вьювер после совместимой сборки публикует `/simulation/les-capabilities.json`
с контрактом `uvyazka.les-viewer.v1`. Источник из LES открывается по параметрам
`project`, `les_dataset`, `les_object`, `les_sha256`. Параметры захватываются до
восстановления рабочего места и нормализации URL; произвольные пути не принимаются.

`web/src/les-source.ts` дочитывает свойства через обычный API, проверяет SHA
оригинала и ID объекта, выводит свойства в безопасном текстовом представлении.
Большие целые свойства отображаются исходными цифрами, null отличается от нуля.
Полнота чтения/инженерное утверждение из наличия свойств не следуют.
Подсветка допускается только для однозначного native ID в той же редакции и проекте.
Нет однозначной геометрии — остаются свойства и объяснение, другой объект не выбран.

Для RVT/IFC приёмник ищет сохранённую сцену по SHA-256 оригинала, проверяя все
страницы каталога. Совпадение имени файла недостаточно; несколько подходящих
сцен не выбираются автоматически. Само чтение свойств не создаёт геометрию.
В сцене дополнительно проверяются проект, редакция, native ID и наличие mesh.

Для DWG/DXF доступно действие «Показать на чертеже». `/api/models/original`
принимает только зарегистрированные проект/снимок/объект/SHA, без пути. Сервер
проверяет точные выдаваемые байты через временный spool, браузер независимо
сверяет SHA перед передачей существующему CAD-приложению. Общий предел — 64 МиБ.
CAD-приложение должно подтвердить готовность сцены и выделение единственной
сущности с исходным handle. Совпадения по имени и выбор соседнего объекта нет.
Объекты блоков, непрочитанная графика и неоднозначные ID оставляют свойства
и объяснение ограничения. Автоматическое создание BIM-сцен и поиск по геометрии
этот маршрут не реализует.

Статические ресурсы `/simulation/` поддерживают HEAD с теми же заголовками,
что GET, и без тела: CAD SDK проверяет так доступность локальных worker-файлов.
На API HEAD не перенаправляется. Маркер возможностей поставляется вместе
с фронтендом и сервером, а не отдельно от них.

Проверка отдельного кандидата: создан синтетический DXF и прочитан настоящим
ezdxf. В браузере ссылка LES открыла его свойства; «Показать на чертеже»
открыло оригинал и выделило надпись с соответствующим handle в инспекторе.
Первый прогон выявил отсутствие HEAD на сервере; после исправления путь
повторён. Это проверка перехода во вьювер, не поиска RAG, всех DWG/RVT
или установленной пользовательской пары. Рабочие приложения не переключены.

Приёмник нужно поставлять вместе с его маркером возможностей. Старый установленный
вьювер не становится совместимым от одного изменения исходников. До обновления
LES предлагает установить/обновить Увязку через официальную страницу GitHub Releases.
Установщик не скачивается и не запускается скрыто. Прямое чтение всех вариантов
DWG/RVT и сквозная приёмка установленной пары этим контрактом не подтверждаются.
