# Л.И.С.Т.: что полезно Увязке

Проверено 20 октября 2026 года: [proovcme/les-list](https://github.com/proovcme/les-list),
версия 0.2.1, commit `f6bedb34eff75c2d47e772810220ff738183f804`, лицензия MIT.
Это оценка прочитанного кода и синтетических тестов, а не испытание
точности на полном реальном комплекте ПД/РД. Код Л.И.С.Т. в Увязку пока не включён.

## Решение

Л.И.С.Т. подходит как **необязательный читатель структуры и таблиц**.
Не требуется переносить чат Л.Е.С., локальную модель, Qdrant или второй
пользовательский интерфейс. Standalone-пакет уже имеет CLI и Python API;
его зависимости — PyMuPDF и PyYAML.

Модель получает кандидатов разделов, штампов и таблиц, выбирает источники,
проверяет смысл и сохраняет наблюдения в базе Увязки. Тип таблицы или
предположение о принадлежности тому не становится инженерным выводом.

## Что реализовано

| Возможность | Применение в Увязке |
|---|---|
| Штампы, шифры, стадии, состав томов, указатели страниц | Первый проход и адресная карта чтения |
| Каталог таблиц: документ, страница, bbox, заголовок, версии алгоритма и детектора | Возврат к конкретной таблице без перечитывания проекта |
| Повторное обнаружение таблицы в исходном PDF, проверка SHA-256 и геометрии | Подтверждённое извлечение отдельно от поисковой карточки |
| Нормализаторы ХВС, водных балансов, экспликаций, электрических таблиц | Предложения структуры строк с сохранением исходных ячеек |
| Виртуальные тома, основания группировки, состояния partial/ambiguous | Показ неоднозначности состава |

## Ограничения для адаптера

1. **Кандидат не равен установленному факту.** Типы и принадлежность разделу
   определяются правилами и словарями. Значения confidence назначаются кодом;
   это не доказанная вероятность правильности. Модель должна иметь возможность
   исправить классификацию и читать нераспознанные таблицы.
2. **Полнота чтения.** В folder extractor по умолчанию не более 260 страниц
   на PDF. `read_project_table` возвращает максимум 500 строк, включая шапку,
   с `truncated`, но без `offset`. Нужны продолжение чтения и журнал
   обработанных исходных строк. Пропущенные страницы не считаются проверенными.
3. **Версия файла.** Fingerprint сравнивает одновременно SHA-256, размер и
   `mtime_ns`. Изменение времени файла может дать `stale` при одинаковых
   байтах. В Увязке идентичность содержимого должна опираться на хеш; время —
   сигнал для повторной проверки.
4. **Один снимок для проверки и чтения.** Хеширование файла и открытие
   PyMuPDF происходят раздельно. Для импорта доказательств следует читать
   проверенный снимок байтов, чтобы замена файла между этими операциями
   не связывала новые строки со старым хешем.
5. **Границы проекта.** Sidecar хранит пути источников. Нельзя открывать их
   напрямую из произвольного импортированного JSON. Сначала сопоставить путь
   с зарегистрированным `doc_id`, проверить корень проекта и SHA-256.
6. **Сканы и нестандартная графика.** Рассмотренный exact reader использует
   `find_tables()` и текстовый слой. Нужен отдельный визуальный/OCR-проход,
   если они не дали результата. Ноль обнаруженных таблиц не означает их отсутствие.
7. **Строка и ячейка.** Сохранять исходную матрицу рядом с нормализованными
   полями, номера строк и происхождение. Многоуровневая шапка, объединения,
   пустоты, единицы и переносы требуют проверки моделью.
8. **Координатные рамки.** Перед связью bbox с видами Увязки проверить
   rotation/cropbox. Измерения используют `pdf_unrotated_top_left_points`;
   нельзя принять bbox стороннего детектора за ту же рамку без проверки.

## Контракт интеграции

```text
Документы, зарегистрированные в Увязке
  → Л.И.С.Т. строит производный каталог по выбранным документам
  → адаптер связывает карточки с project_id / doc_id / SHA-256
  → модель выбирает таблицу и область чтения
  → точное извлечение + исходные ячейки + адреса + покрытие
  → модель сопоставляет строки, единицы, сущности и смысл
  → инструменты Увязки сохраняют наблюдения, связи, вопросы и ревизии
```

Sidecar — перестраиваемый индекс. SQLite Увязки — память проекта,
включая решения модели и человека, измерения и историю.
Никаких автоматических «принятых значений» при импорте.
Достаточно небольшого адаптера и ограниченных операций поиска/чтения;
отдельный MCP-сервер для каждого нормализатора не нужен.

Первый полезный сценарий: найти экспликации АР и смежных разделов,
прочитать все строки, предложить соответствия помещений и показать
расхождения номеров, названий и площадей с адресами источников.
Сопоставление выполняет модель; код проверяет числа и сохраняет результат.

## Проверка

- Код изучен в отдельном локальном клоне.
- На Windows, Python 3.13: **128 passed, 7 skipped**.
- Семь пропусков — тесты кириллических PDF-штампов и схем, которым нужен
  шрифт по предусмотренному в их фикстурах пути.
- Первый запуск упёрся в права существующей общей папки pytest; повтор
  с новой отдельной временной папкой прошёл. Это проблема окружения.
- Не измерялись precision/recall на реальных проектах, время полного
  обхода больших комплектов и качество OCR.
