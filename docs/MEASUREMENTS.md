# Постоянная память измерений для модели

Модель определяет, что изображено, выбирает виды и контрольные размеры,
задаёт контуры и проверяет их по источнику. Инструменты выполняют геометрические
операции и сохраняют результат. Собственного LLM-клиента или обязательной
генерации по API нет.

## Реализованный сценарий

Зарегистрированный PDF → изображение и координаты → выделенные моделью виды →
отдельная калибровка каждого вида → длина/площадь → контур поверх PDF →
проверка или вопрос агента → продолжение после перезапуска MCP →
исправление масштаба и пересчёт с сохранением истории.

Все записи лежат в существующей `projects/<project_id>/project.sqlite3`.
Таблица `drawing_records` содержит неизменяемые версии видов, калибровок и
измерений; `drawing_requests` обеспечивает повтор вызова без дублей.
Операции отмечаются в общем журнале `events`. Исходные PDF не перезаписываются.
Новая сессия использует тот же каталог `UVYAZKA_HOME` и тот же проект.

| Инструмент | Результат |
|---|---|
| `inspect_measurement_sheet` | Рамка PDF-страницы, исходный поворот, слова или векторные примитивы и их координаты; чтение частями |
| `save_drawing_view` | Область, тип и смысл вида, источник и версия |
| `calibrate_drawing_view` | Две контрольные точки, реальная длина, основание и масштаб данного вида |
| `measure_drawing_view` | Атомарный пакет длин или площадей с исходными контурами |
| `get_drawing_measurements` | Текущее состояние или история, продолжение, признаки устаревания |
| `recalculate_drawing_measurements` | Новые версии результатов после исправления масштаба |
| `review_drawing_measurements` | Сохранённая проверка или вопрос агента |
| `render_drawing_measurements` | PNG источника с контурами и преобразованием координат снимка |

Подробный порядок и ограничения координат:
[инструкция для агента](../skills/aec-project-reader/references/view-measurements.md).

## Значение статусов

`agent_proposed` — интерпретация вида или калибровки предложена моделью.
`calculated_unreviewed` — инструмент вычислил геометрию, смысл ещё не проверен.
`agent_checked` — агент сообщил о проверке; инструмент не доказывает факт осмотра.
`question` — сохранён нерешённый вопрос.

Устаревание возвращается отдельно: изменился источник, вид или калибровка.
Проверка исходника сверяет байты с SHA, а не только время изменения.
Ранее рассчитанное значение остаётся в истории со своими основаниями.
Ни один статус не означает утверждения ответственным инженером.

## Что ещё требуется для всей базы проекта

Это первый рабочий сценарий, а не завершённый универсальный разбор ПД/РД.
Следующие слои должны использовать те же источники, версии и границы проекта:

1. **Знания об оформлении:** проверенные требования, редакции, область применения,
   формы и условные обозначения. Требование стандарта, практика организации
   и эвристика распознавания хранятся раздельно. Новый стандарт сам по себе
   не устанавливает применимость к ранее выпущенному проекту.
2. **Типы таблиц:** ведомости документов/листов; экспликации; спецификации;
   ведомости отделки; нагрузки и потребители; кабельные журналы; балансы
   расходов; ВОР и сметные таблицы. Для типа нужны смысл граф, единицы,
   правила продолжения, объединённых ячеек и итогов, источник шаблона.
3. **Ожидаемый состав:** объект, стадия, задание и установленные требования
   определяют ожидаемые комплекты. Непереданный файл не равен отсутствующему
   проектному решению.
4. **Фактическая структура:** документ → версия → лист → вид/таблица → запись.
   Файл может содержать несколько документов. Номер PDF-страницы отличается
   от номера листа. Таблица может продолжаться на нескольких листах.
5. **Представления объектов:** план, разрез, схема и строка спецификации могут
   описывать один объект. Связи подтверждаются по контексту и источникам;
   одинаковая марка в разных корпусах не объединяется автоматически.
6. **Покрытие и зависимости:** реестр непроверенных областей и строк, принятые
   соответствия, распространение изменений на ВОР, смету и график.

Шаблоны помогают модели выбрать инструменты. Неузнанная форма должна оставаться
доступной как изображение, текст и геометрия. Неподдерживаемое измерение
не превращается в ноль или в автоматически угаданную величину.

## Проверка

Синтетический PDF с двумя видами, разными масштабами и поворотом страницы:
сохранение и повторное открытие базы; отдельные площади; исправление масштаба;
история; сброс отметки проверки; отказ при подмене исходника и смене вида;
откат всего ошибочного пакета; повтор запроса; разделение проектов;
проверка координат наложения на PNG и неизменности PDF.

Протокольная проверка запускает два независимых stdio-процесса MCP:
первый записывает вид, калибровку и измерение; второй читает результат
и возвращает изображение через официальный MCP-клиент.
Это проверка протокола, не подтверждение работы во всех настольных клиентах.

```powershell
python -m unittest discover -s tests -p test_measurements.py -v
python -m unittest discover -s tests -p test_mcp.py -v
```

Первый выпуск предназначен для локального MCP. Публичный браузерный вьювер
пока не подключён к этим таблицам; новых кнопок измерения на VPS этот выпуск
не добавляет. Чтение PDF требует extra `readers`; геометрические расчёты
не требуют BIM-библиотек или вызова модели.
