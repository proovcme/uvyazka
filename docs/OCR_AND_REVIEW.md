# OCR, единицы и результаты проверки

Нейросеть определяет, какие документы и объекты соответствуют друг другу,
формулирует условия проверки и проверяет смысл таблиц. Инструменты сохраняют
основания и выполняют явные операции. Совпадение чисел не означает принятие
инженерного решения.

## Сканированные PDF

`read_evidence` возвращает `low_text` для страницы с малым количеством текста.
Это сигнал проверить страницу визуально: он не доказывает, что перед нами скан.
Для скана агент вызывает `ocr_pdf_pages(project_id, doc_id, pages, request_id)`.
За вызов допускаются 1–5 физических страниц PDF, файл до 64 MiB, 150–400 DPI.
Оригинал должен быть зарегистрирован и совпадать с сохранённым SHA-256.

OCR работает локально через Tesseract, без внешнего сервиса и API модели.
Нужны PyMuPDF из extras readers и установленный Tesseract с rus/eng traineddata.
Бинарник ищется в PATH и стандартной папке Windows Tesseract-OCR; иной путь
задаётся UVYAZKA_TESSERACT. Языки передаются явно, по умолчанию rus+eng.
Один процесс ограничен 90 секундами, растр — 20 млн пикселей. Если большой
лист требует уменьшения разрешения, actual_dpi отражает фактическое значение.
Отсутствующий движок/язык или ошибка не заменяются выдуманным текстом.

По умолчанию страницы с текстовым слоем пропускаются. Для испорченного слоя
агент может явно задать force=true. Результат содержит engine/version, язык,
DPI, физическую страницу, bbox слов и confidence. word_limit=0–40 и
word_offset ограничивают выдачу координат; confidence не является гарантией
правильности. Координаты относятся к повёрнутой отображаемой странице,
начало — её левый верхний угол, единица — PDF point.

Снимок сохраняется в SQLite выбранного проекта; старые страницы и версии
извлечения остаются доступными. Текст индексируется для search_project и
читается полностью через read_evidence с выданным parser_revision. На OCR
можно сослаться в record_observations; статус остаётся source_observation.
Повтор идентичного request_id берёт кеш, повтор с другими параметрами
отклоняется. Повтор старого запроса после нового снимка не откатывает базу:
он отмечен historical_snapshot. Обычный scan сохраняет OCR-снимок, пока
хеш исходника и базовая версия читателя не изменились.

## Единицы

Общий словарь содержит геометрию, ВОР/сметные измерители, расход, давление,
электрические и теплотехнические величины, нагрузки, трудозатраты и финансы.
Через get_unit_catalog модель получает нужную группу и базовую единицу допуска.
Множители считаются точно, для °C учитывается сдвиг; часы, чел.-ч и маш.-ч
разделены. [Поддержанные единицы и ограничения](PROJECT_UNITS.md).
Вид величины, основание измерения, ревизия и спецификация должны совпадать;
неизвестная единица не считается числовым расхождением.

## Три группы результатов

- discrepancy — воспроизводимое расхождение в сопоставимых переданных данных;
- question — неоднозначность, неизвестная единица, основание или правило;
- unchecked — неразобранный документ/раздел, отсутствующее значение или
  подключение, состав которого пока нельзя проверить по заданному покрытию.

finding_counts считает группы отдельно. Совпавшие количественные сопоставления
имеют категорию match. Устаревшее сопоставление относится к unchecked.
Совместимые значения с разными числами — discrepancy; пропуск не равен нулю.
Если подключение не задано в графе при незавершённом разборе источников,
оно не объявляется дефектом проекта. Проверка по допущенному требованию
остаётся вопросом, пока у самого требования нет источника.

issue_count сохранён как общее количество пунктов, а не ошибок проекта.
get_project_issues принимает category для фильтра с отдельной пагинацией.
Старые отчёты не перезаписываются: для прежних неразделённых сравнений
показан вопрос и reaudit_recommended. Новый audit_project_graph создаёт
отдельный снимок новой версии проверок. project_error_confirmed=false:
автоматическое правило не подтверждает инженерную ошибку проекта.
Поле project_status.questions сохранено как совместимый прежний счётчик
всех незакрытых сопоставлений; для новых интерфейсов используется finding_counts.

## Таблицы и инженерная интерпретация

OCR не восстанавливает автоматически смысл таблицы. Агент отдельно проверяет:
многострочные заголовки и их область действия; объединённые ячейки; переносы
на следующую страницу; единицы на уровне столбца/строки; подытоги и исключение
двойного счёта. Сохраняются исходный текст, координаты и принятое толкование.
Флаг table_structure_verified=false запрещает трактовать удачное распознавание
цифр как подтверждённое восстановление структуры. Прочерки, пустые ячейки,
диапазоны и неразборчивые знаки остаются вопросами, а не нулями.
