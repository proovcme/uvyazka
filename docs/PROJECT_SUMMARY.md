# От извлечённого текста к сводке проекта

Регистрация документов и поиск по тексту сами по себе не создают паспорт
проекта. После буквального чтения приём запускает отдельный этап `summarizing`:
собирает числовые кандидаты из сохранённых страниц и блоков. Повторное чтение
оригиналов или вызов модели для этого не нужны.

## Что получает человек

Обзор показывает состав по папкам и форматам, покрытие чтения, найденные
табличные ТЭП и записанные наблюдения. «Найденные данные» доступны с поиском,
предварительной группой и постраничной выдачей. В разделах мощностей, объёмов
и финансов видны соответствующие кандидаты и отдельно записанные наблюдения.
У каждого фрагмента открывается исходная страница или строка таблицы.
После нового приёма интерфейс открывает сводку полученного `project_id`.

Число кандидатов означает число вхождений в источниках. Оно включает повторы,
справочные значения и неподходящие контексты; это не количество уникальных
показателей здания. Например, запись «2020 г» может быть распознана как
кандидат с единицей массы. Разбор контекста остаётся работой модели.

## Что получает модель

1. `project_status` — покрытие и состояние автоматической сводки.
2. `get_project_summary(project_id, query, group, offset, limit)` — состав,
   кандидаты и точные ссылки на извлечение. Предел выдачи — 50 записей,
   по умолчанию 30. Продолжение — `next_offset`.
3. `read_evidence` по `source` кандидата — заголовки, контекст и свежесть.
4. `record_observations` — запись выбранного показателя с проверенным смыслом,
   областью измерения и буквальным значением. Такая запись остаётся
   `source_observation`; инженерное принятие автоматически не выполняется.

Для старого проекта или обновления алгоритма есть
`build_project_summary(project_id, page_limit=500)`. Он обрабатывает не более
2000 ещё не подготовленных блоков за вызов. Продолжать, пока
`remaining_blocks` не станет нулём; отсутствие прогресса при ненулевом остатке
требует проверки состояния источников. Новый приём делает это сам.

Запросы чтения не создают таблицы и не запускают скрытый разбор проекта.
HTTP `/api/summary` и MCP используют одну реализацию и ту же SQLite.

## Что извлекает автоматика

- Число с явно написанной поддержанной единицей в текстовом блоке.
- Значение справа от отдельной ячейки единицы в строках DOCX, Excel и CSV.
  Сохраняются строка, столбец, а для Excel — адрес ячейки.
- Исходное написание, нормализованный скаляр, контекст, единица,
  предварительная группа и ссылка с DOC-ID, SHA-256, версией читателя и
  номером блока. Диапазон или допуск сохраняется буквально без сведения
  к одному числу. Прочерк не превращается в ноль.

Алгоритм не восстанавливает единицы из удалённого заголовка, не читает
геометрию DWG/RVT, не выполняет формулы и макросы, не делает OCR автоматически.
Для таблиц с объединёнными заголовками, сложных спецификаций и экспликаций
нужны адресное чтение таблицы и проверка моделью. Отсутствие кандидата не
доказывает отсутствие показателя в документе.

Предел — 300 кандидатов на блок; `truncated_blocks` явно сообщает о блоках,
требующих дополнительного адресного разбора. `indexed_blocks / total_blocks`
относится только к тексту текущего успешного извлечения. Непрочитанные форматы
и ошибки читателей показываются отдельно в покрытии проекта.

## Версии и смысл

`quantity_pages` и `quantity_candidates` хранят результаты с версией алгоритма,
хешем источника и версией читателя. Повторный запуск не дублирует записи.
После обновления исходника прежние кандидаты остаются в истории, но не
попадают в текущую сводку. Изменение файла вне нового сканирования видно
через свежесть источника и требует обновления чтения.

Автоматическая группа — подсказка для поиска. Алгоритм не назначает
действующую проектную ревизию, не склеивает помещения по похожему названию,
не суммирует ведомости и не принимает совпадения за проверку проекта.
Сопоставления строятся по явно записанным наблюдениям и их основаниям.

Проверки реализации: синтетические тесты скаляров/диапазонов, ограничений,
инкрементального кеша, изоляции версий и чтения без записи; HTTP-приём →
кандидат → источник → наблюдение; MCP stdio с перезапуском. Они не заменяют
визуальную приёмку интерфейса или смысловой аудит реального проекта.
