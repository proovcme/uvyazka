# Вьювер и расчёт в браузере на locia.work

[Открыть демо](https://locia.work/uvyazka/).

Это отдельная сборка того же вьювера. Можно открыть собственный DWG/DXF/IFC/RVT или
готовые опубликованные примеры. Rust WASM конвертирует RVT с сохранёнными сетками,
web-ifc читает модель, Pyodide выполняет тот же Python-планировщик и движок
симуляции. Тяжёлые операции идут в workers с отменой. VPS раздаёт статические
файлы: пользовательская модель на сервер не отправляется. Revit, MCP,
ИИ-клиент и серверная база для этого пути не нужны.

По умолчанию открыт «Просмотр»; расчёт и проигрывание находятся в «Симуляции».
DWG/DXF открываются отдельным CAD-приложением со слоями; расчёт по линиям не выполняется.
[Покрытие форматов и проверки](VIEWER.md).

Для IFC/RVT доступны выбор базового/усиленного сценария, множитель доступности ресурсов,
выдержка бетона, повторный расчёт, проигрывание, CSV, журнал JSON, диагностика
и скачивание IFC из RVT. После первого расчёта повторный расчёт работает без сети
в той же вкладке. Перезагрузка страницы или отмена worker потребует загрузить
модули снова; офлайн-установщик и восстановление сессии не реализованы.

В ранее опубликованном прототипе: RVT 64 MiB, IFC 128 MiB, 10 000 продуктов, 128 MiB упакованной
геометрии, 20 000 операций. Фактический расход памяти больше размера файла.
В текущей сборке первые четыре порога сняты; добавлены выбор бюджета
IFC-движка и сохраняемый журнал. [Актуальные ограничения](VIEWER.md#ограничения-чтения).
Также доступен каталог видов, листов, определений спецификаций
и сохранённых ячеек. Оформленная графика видов/листов и вычисленное тело таблиц
не воспроизводятся. Стадии RVT в браузере пока не извлекаются;
непрочитанные стадии явно показаны; существующие/сносимые элементы
автоматически не исключаются. Геометрические коробки и неизвестные тела RVT
не дают объёмы работ. EXPRESS-валидация в браузере не выполняется.
[Проверка и найденные ограничения](BROWSER_VALIDATION.md).

По умолчанию открывается **Medical-Dental Clinic**: архитектура с 2620 физическими
элементами и 269 помещениями. В верхней полосе можно выбрать архитектуру,
вентиляцию, электрику, сводную модель из трёх разделов, учебный каркас или
**RVT · инженерия RE1**. Последний пункт скачивает публичный RVT того же сайта,
проверяет SHA-256 и запускает тот же worker, что используется для своего файла.
Это не показ заранее сконвертированной геометрии под видом чтения RVT.
Проверенный RE1 (Revit 2025) даёт 74 элемента с геометрией; покрытие остаётся
частичным и не означает поддержку любого файла или всех версий Revit.

**Данные модели** открывают таблицы элементов, помещений, этажей и систем,
поиск по сохранённым параметрам, карточку исходной записи и экспорт текущей
выборки в JSON / CSV параметров. Записи без геометрии тоже доступны в данных.
В свойствах отдельно показаны Revit ElementId, Revit UniqueId, IFC GlobalId и
ID сцены. Для IFC из Revit числовой Tag показан с явным основанием экспорта;
он не подменяется STEP-ID. Непрочитанный ID остаётся неизвестным. Значения
можно выделять и копировать, рядом есть кнопки копирования и копирование всей
карточки. Поиск в структуре и данных включает ID, имена, материалы, системы
и параметры; `revit:12345` ищет точный ElementId.
Большой расчёт показывает реально завершённые работы и отдаёт управление
между порциями событий для ответов на heartbeat. Индекс готовых работ движка
0.1.2 устраняет повторную проверку всех зависимостей на каждом событии;
порядок назначения ресурсов сохранён. График остаётся предварительным.
Для нестандартных IFC-ведомостей сохраняются явные количества с именем набора,
единицей, ID величины и исходным числом; исходный ноль сохраняется. Если единица
не определена, она остаётся неизвестной. Обмеры сеток хранятся отдельно и не
подменяют исходные количества. Сырые свойства могут не иметь прочитанных единиц.

Клиника содержит повторяющиеся помещения в разных разделах. Автоматического
объединения или суммирования площадей нет. В сводке 8442 физических элемента;
совмещение по исходным координатам не означает проверенную координацию.
В IFC клиники явные системы отсутствуют; это не доказывает их отсутствие
в проекте. Для RVT отдельно доступны прочитанные виды, определения спецификаций
и сохранённые ячейки. Оформленная графика и вычисленные таблицы Revit не обещаны.

`tools/build_demo_catalog.py` получает только закреплённые публичные файлы из
`tools/public-demo-sources.json` и проверяет размеры и хеши. Лицензии и изменения
описаны в [источниках](DEPENDENCIES.md) и опубликованном `demo/ATTRIBUTION.txt`.
Оригиналы и производные модели не коммитятся. Прежний каркас из 22 элементов
с двумя рассчитанными сценариями остаётся отдельным примером. Технологии,
выработки и выдержки бетона в сценариях — допущения, а не утверждённый ПОС/ППР.

## Сборка

Проверка обновления 2026-10-23: 76 web-тестов; 168 Python-тестов и 54 subtests
(4 проверки пропущены); сравнение со старым ядром на 60 случайных DAG —
совпали события, ресурсы, снимки/восстановление и CPM. Полный сценарий архитектуры
клиники завершился в CPython за 22,7 с вместе с подготовкой: 8434 работы,
59129 событий, 577 элементов вне графика. Это не замер скорости браузера.
WASM-конвертер и web-IFC-адаптер, запущенные в Node на RE1-Mechanical.rvt,
дали 74 элемента с геометрией, 5 систем, 29 записей каталога и 73 записи
спецификаций/параметров. Экспорт данных проверен отдельно от UI. Эти проверки
не подтверждают визуальную приёмку новой сборки или работу буфера обмена
в конкретном браузере пользователя.

Установите Python 3.11+, uv, Node.js 22.12+, Rust и wasm-bindgen-cli 0.2.129.
В корне репозитория:

```powershell
uv sync --extra all --extra authoring
cd web
npm ci
cd ..
npm --prefix integrations/cad-viewer ci
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129 --locked
uv run python tools/build_browser_runtime.py
uv run python tools/build_demo_site.py
```

Результат: `.uvyazka-build/public-site/uvyazka/`.
Для локального просмотра запустите
`uv run python -m http.server 8774 --directory .uvyazka-build/public-site`
и откройте `http://127.0.0.1:8774/uvyazka/`.
В каталог публикации должны попасть только index.html, assets,
THREE-LICENSE.txt, demo, cad, runtime, downloads и release.json; служебный соседний
synthetic-cache не публикуется. Страница downloads объясняет установку
локального инструмента и ограничения публичного демо.

Для публикации пакетов текущей версии сначала выполните `uv build`, затем
`uv run python tools/build_demo_site.py --with-downloads`. В downloads попадут
только wheel и исходный архив с текущей версией из pyproject.toml и их SHA-256.
Нативных исполняемых файлов в них нет. release.json фиксирует Git-ревизию,
версию и контрольные суммы всех опубликованных файлов. Собирайте из чистой
зафиксированной ревизии; перед загрузкой проверьте содержимое архивов.

Основная локальная сборка остаётся отдельной: `npm run build` в web.
Она использует `/simulation/` и локальный API выбранного проекта.

## Публикация

### Дерево, видимость и поиск

В RVT-узле дерева доступны также листы, виды, спецификации и размещения.
Поиск по имени/ID охватывает документы; геометрические фильтры не скрывают
их сохранённые записи. Каталог работает и после неудачи конверсии 3D.
Локальная версия связана с общей базой MCP; публичный сайт использует
браузерный кеш и экспорт JSON для переноса в локальный проект.
[Общий каталог](RVT_DATA.md#общий-каталог-человека-и-модели).

Дерево содержит все физические элементы выгрузки: исходная модель → категория →
элементы. Для RVT используются прочитанные категории Revit (Other.Category),
для IFC — классы IFC, в том числе у IFC, экспортированного из Revit. Если
категория RVT не прочитана, это видно в названии ветки. Переключатель
«По уровням» добавляет уровень перед категорией. Категории раскрываются порциями по 50 строк; ограничения
первыми 1000 элементами нет. Выбор элемента на модели раскрывает его ветку и
страницу. Записи без прочитанной геометрии остаются доступны для чтения свойств.

Флажок показывает или скрывает элемент либо всю ветку. Частично включённая
ветка имеет промежуточное состояние. «Только» изолирует ветку; в свойствах
выбранного элемента доступны «Скрыть», «Показать», «Только этот». Скрытые записи
остаются в дереве. «Показать всю модель» сбрасывает скрытие, изоляцию и фильтры.
Выбор видимости сохраняется при смене режима и расчёта для того же model_id;
это состояние просмотра текущей сцены, исходные данные и журнал расчёта сохраняются.

Отдельная строка «Найти элемент» ищет название, семейство, тип и идентификаторы.
`#123` ищет точный IFC step ID, `#ar:123` — точный ID сцены, `revit:123` —
точный прочитанный Revit ElementId. Числа из несвязанных свойств не засоряют
результаты этого поиска. В раскрываемом блоке «Поиск по параметрам» можно задать
имя параметра, условие и значение; имя и значение должны совпасть в одном поле.
«Добавить условие» закрепляет его в списке; условия объединяются через «И» или
«ИЛИ». Уровни и категории выбираются по несколько и сочетаются с системой,
простым поиском и условиями по параметрам. Пустой выбор уровней/категорий означает все.
Ноль считается заполненным значением, null, пустая строка и отсутствующее поле
различаются с нулём. Числовые условия применяются к числам и чистым числовым
строкам в единицах источника; строки с суффиксом единицы и небезопасные большие
целые не преобразуются незаметно. Для них доступны текстовые условия.
По умолчанию выборка применяется к дереву и видимости в 3D. Снимите галочку
«Применять фильтры к 3D», чтобы искать только в дереве. Ручное скрытие действует
независимо от фильтров: очистка поиска не возвращает вручную скрытый элемент.
«Показать» для выбранного элемента вне текущей выборки отключает применение
фильтров к 3D, сохраняя условия поиска. «Только найденные» изолирует выборку в 3D.
Кнопки «Скрыть найденные» и «Показать» действуют на всю выборку, включая строки
на ещё не раскрытых страницах.

DWG/DXF открывается в отдельном CAD-приложении: дерево «файл → слой → объекты».
Доступны поиск по handle, типу и слою, скрытие слоя/объекта, изоляция слоя,
восстановление видимости и копируемые основные свойства объекта. Дерево
обновляется подтверждённым состоянием CAD-движка; для объекта без прочитанного
состояния сцены флажок недоступен. Состояние просмотра не записывает DWG обратно. При переходе с BIM на DWG
карточки BIM-источников и ресурсы симуляции скрываются, свойства заменяются
данными открытого чертежа.

Проверка обновления 2026-10-24: 92 web-теста, в том числе DOM-тест реальной
обвязки поиска/уровней/видимости и тест протокола CAD с заглушкой движка.
Обе сборки и проверка TypeScript прошли. На ранее извлечённом публичном RVT
проверены 74 элемента в шести прочитанных категориях Revit. Это проверки
данных и кода, без визуальной приёмки экрана браузера.

Для моделей свыше 2000 физических элементов просмотр ограничивает плотность
пикселей до 1.25 и отключает тени; объекты, геометрия и свойства сохраняются.
Контуры ограничены бюджетом рёбер. Неизменившиеся материалы не обновляются
на каждом кадре, журнал симуляции при движении вперёд читается последовательно;
перемотка назад восстанавливает состояние из исходного журнала. Поиск повторно
использует индекс свойств текущей ревизии. Прямой переход к примеру не открывает
перед ним модель по умолчанию. Эти изменения проверены тестами кода; измерение
FPS и визуальная проверка в конкретном браузере остаются отдельной проверкой.

Сборка включает предварительно сжатые `.gz` для JSON, геометрии и runtime;
исходные файлы и их данные сохраняются. `file_server { precompressed gzip }`
позволяет выдавать их с известным Content-Length. На проблемном сетевом маршруте
это не устранило зависание крупных ответов: перед включением проверяйте загрузку
полного тела и SHA-256 с клиентской машины, а не только HTTP 200 или работу на VPS.

### Резервная статическая публикация

Публичную сборку можно разместить на GitHub Pages:
`uv run python tools/publish_pages_demo.py --push`. Скрипт проверяет release.json,
хеш каждого файла, границы путей и допустимые каталоги. Копирует только файлы
манифеста в отдельный временный checkout и публикует ветку `gh-pages`; `main`,
локальные проекты и база не меняются. В настройках Pages выберите `gh-pages` и `/`.
Адрес зеркала: https://proovcme.github.io/uvyazka/.
Модели, лицензии, исходники и runtime совпадают с проверенным статическим выпуском.
Git сохраняет байты артефактов без преобразования окончаний строк; перед push
проверяются и хеши staged-объектов. Сборка добавляет CSP в HTML для хостингов без
настраиваемых заголовков. Ограничения встраивания frame-ancestors и X-Frame-Options
по-прежнему требуют HTTP-заголовков; на VPS они сохраняются.
Переадресацию входа с VPS включайте только после проверки полного скачивания
JavaScript, IFC-пакетов, геометрии, RVT и WASM с клиентской машины.
Для этой проверки используйте
`uv run python tools/check_public_delivery.py https://proovcme.github.io/uvyazka/ --large`.
Команда проверяет полные тела HTTP-ответов и SHA-256 и выводит время передачи;
это не заменяет визуальную проверку в браузере. Переадресации запрещены: проверка
`locia.work` не должна незаметно подтверждать файлы с Pages. Для полной проверки
выпуска, включая скачиваемые пакеты и архивы исходников, используйте `--all-files`.
`--timeout` задаёт тайм-аут сетевых операций; время передачи каждого файла выводится
отдельно. На медленном соединении полный архив может скачиваться дольше минуты.

Основной адрес `https://locia.work/uvyazka/` обслуживается непосредственно VPS.
GitHub Pages остаётся отдельным резервным адресом. Канонический вход сохраняет хост:

```caddyfile
redir /uvyazka /uvyazka/ 308
```

На VPS сохраняются текущий статический выпуск и предыдущий выпуск для отката.
При обновлении зеркала дождитесь успешного deployment Pages и проверьте
`--all-files --revision <SHA>` с клиентской машины. VPS проверяйте отдельно. Проверки
`deploy_static_site.py` запрещают переадресации и требуют совпадения всего манифеста,
включая хеши скачиваемых пакетов. При действующем перенаправлении сначала подготовьте
отдельный маршрут проверки origin; зеркало не может служить подтверждением выкладки
на VPS. Если для аварийного восстановления включено перенаправление на зеркало,
снимайте его после полного скачивания файлов с origin и проверки страницы в браузере.

Содержимое собранной папки можно обслуживать статическим сервером в `/uvyazka/`.
Все runtime-зависимости включены в сборку, CDN не используется. Для CSP нужны
script-src 'self' 'wasm-unsafe-eval', worker-src 'self', connect-src 'self', img-src 'self' data: и
style-src 'self' 'unsafe-inline' для вычисляемых полос графика.
Не публикуйте локальную базу или порт панели вместо статической сборки.
На locia.work демо развёрнуто отдельно от основного приложения сайта.
Для локальной проверки с такими же заголовками используйте
`uv run python tools/serve_browser_demo.py` (порт 8779).

Для `/uvyazka/cad/*` нужен отдельный маршрут с `frame-ancestors 'self'`
и `X-Frame-Options: SAMEORIGIN`; корневая страница сохраняет запрет встраивания.
Исходники CAD и лицензии публикуются в `cad/sources.html`. Обычный unsafe-eval
не разрешается: сборка проверяет и исправляет две фабрики Emscripten.

### Обновление существующего VPS

`tools/deploy_static_site.py` запускается на VPS для уже настроенного маршрута.
Он принимает архив содержимого публичной сборки, SHA-256, Git revision и уникальное
имя выпуска. Большие архивы загружайте в каталог на диске, например
`/var/www/uvyazka/incoming/`, а не в `/tmp`: на некоторых Linux-системах `/tmp`
расположен в tmpfs и расходует RAM и swap. После подтверждённой выкладки удалите
её входной архив; каталог выпуска и предыдущий выпуск остаются для отката.
Проверяет состав и хеши всех файлов по release.json, запрещает
ссылки и выход за каталог, затем атомарно переключает `/var/www/uvyazka/current`.
После переключения проверяет полный HTTPS-манифест, страницу, WASM и CAD без
