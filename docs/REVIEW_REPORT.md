# Сверочная ведомость выбранной проверки

Ведомость превращает сохранённую работу модели и человека в переносимый
результат: что исследовано, на каких основаниях, какие вопросы остаются
и что ещё не прочитано. Оригиналы не изменяются; экспорт не утверждает проект.

## Через панель

Откройте **Листы и таблицы → Проверки и продолжение**, выберите задачу.
Ссылки «Ведомость Markdown», CSV и JSON выгружают **весь выбранный состав**,
включая пункты за пределами открытой страницы. Версия задачи фиксируется
в ссылке. Свежесть источников и выводов проверяется заново при скачивании.

- Markdown — читаемый документ с пояснениями и ссылками на источники.
- CSV — одна строка на условие, разделитель `;`, UTF-8 с BOM. Метаданные
  и границы повторены в строках, чтобы не потеряться при фильтрации.
  Строки, похожие на формулы, экранированы для табличных редакторов.
- JSON — структурированный снимок `uvyazka-review-report-1` для дальнейшей работы.

Ссылки ведут в локальную панель, из которой скачан документ. Для их работы
она должна быть запущена с той же базой. Файл ведомости можно передавать
отдельно, но доступ к локальным оригиналам другому получателю этим не предоставляется.

## Через MCP

```json
{
  "project_id": "object-a",
  "task_id": "pump-check",
  "format": "markdown",
  "panel_url": "http://127.0.0.1:8772"
}
```

Вызов `export_review_report` возвращает `filename`, `content_type`, `content`.
Клиент сохраняет content в файл; сервер сам не выбирает место записи.
Допустимы `format=json|csv|markdown`; по умолчанию JSON.
Опциональный `revision` выбирает историческую версию задачи.
`panel_url` — только HTTP-адрес loopback-панели без пути, логина и параметров.
Без него ссылки относительные. Экспорт не обращается к указанному серверу.

Локальный HTTP-маршрут:
`GET /api/structure/report?project_id=object-a&task_id=pump-check&format=csv`.
Он возвращает сам файл, а не JSON-обёртку MCP.

## Что сохраняется

- Проект, задача, её версия и текущая версия, время формирования, границы.
- Полный фиксированный перечень условий, состояние каждого и следующий шаг.
- Отдельные счётчики работы и результатов актуально разобранных условий.
- Точная ссылка `analysis_id/reader/revision/check_id`, заголовок и пояснение
  **зафиксированного** вывода. Новая редакция не подменяет старую молча.
- Выбранные исходные адреса и зависимости разбора: относительный путь,
  SHA-256, физическая страница PDF либо table_id/row_number, где заданы.
- Ссылки на исходные таблицы/PDF и evidence_cells сохранённого разбора.
- Вопросы, причины блокировки и причины перепроверки.

Источники разбора могут относиться к нескольким условиям. Их наличие в строке
ведомости не означает отдельную независимую проверку каждой ячейки.
Текст вывода и инженерное соответствие по-прежнему задаёт автор разбора.

## Свежесть и границы

Задача и связанные версии разборов читаются в одном снимке SQLite.
Проверяются реальные хеши файлов. Изменение источника, версии обработчика
или линии разбора делает зависимый пункт `needs_recheck`.
Старое заключение видно в `recorded_outcome`, но его текущий `outcome`
становится `unchecked`; оно не попадает в счётчики актуально разобранных.
Историческая задача также оценивается относительно текущих оснований.
Оригиналы старых выдач экспорт не архивирует.

`counts` относится к работе: pending/working/blocked/reviewed/needs_recheck.
`outcomes` считает только актуально reviewed: match/discrepancy/question/unchecked.
Поэтому два blocked отображаются в составе работы, а не как две ошибки
и не как два результата завершённого исследования.

`accepted=false` и `complete_project_review=false` всегда сохраняются.
Совпадение SHA-256 не устанавливает действующую согласованную выдачу.
Экспорт не закрывает замечания, не назначает ответственным полномочия
и не подтверждает правильность инженерного решения.

Максимум одной задачи — 200 единиц. Ответ ограничен 1 MiB; при превышении
возвращается ошибка, строки молча не обрезаются.

## Проверка реализации

Синтетические тесты проверяют экспорт 105 единиц при пагинации UI, сохранение
blocked/вопросов и исходных адресов, устаревание по реальным байтам и новой
версии разбора, историю, разделение проектов, CSV-формулы и локальный HTTP.
Stdio-тест восстанавливает ведомость в новом MCP-процессе; HappyDOM проверяет
ссылки скачивания выбранного проекта и версии. Это не визуальная приёмка браузера.

## Передача ведомости

Экспорт содержит проектные данные, имена источников, относительные пути и
текст замечаний. Он не обезличивает их автоматически. Перед публичным
размещением подготовьте отдельную копию и проверьте её содержимое, включая
названия объектов, реквизиты, количества, параметры оборудования и ссылки.
Для публичных примеров используйте синтетические данные либо материалы,
для которых разрешена публикация соответствующих сведений.
