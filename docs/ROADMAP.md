# Первые этапы

1. **Контракты и переносимый пакет.** Зафиксировать схему проекта/источника/наблюдения,
   MCP-инструменты, формат навыков и клиентские профили. Отделить универсальный код
   исследовательского прототипа от конкретного здания и его путей.
2. **Память проекта.** Реестр и полнота по форматам, извлечение/кеш, точные таблицы,
   пакетное пополнение, ревизии, повторное использование пригодных модулей RAG-Legion.
3. **Подтверждение и сверка.** Наименования, свойства, единицы и база количества;
   источники с изображением спорной строки, арифметика, вопросы и исправления.
4. **Приёмка настольных клиентов.** Сначала Codex на Windows, затем Claude Desktop;
   остальные клиенты после проверки их механизма инструментов и инструкций.
   Общая база должна переживать смену клиента и сжатие диалога.
5. **Интеграции.** Явные адаптеры ЛЕС и CAD/BIM. Семантический поиск, прямой API
   и локальные модели — дополнительные режимы, не условия запуска ядра.
6. **График.** Работы по объектам/зонам/процессам, объёмы, ресурсы, календари,
   зависимости, расчёт и проверка реализуемости директивных сроков.
7. **ПОС/ППР.** Подготовка по согласованной базе и расчётам с видимыми
   незакрытыми инженерными исходными данными и проверкой согласованности выдачи.

Первый критерий: на синтетическом комплекте система проходит все строки,
сохраняет источники, не смешивает два проекта, объясняет различие базы количества
и корректно снимает ложное расхождение после исправления чтения десятичного числа.
Затем повторяется согласованный сценарий на реальном комплекте локально.
