# Сверочная ведомость из RVT без Revit

Локальная смотрелка строит предварительные строки по нативным параметрам
экземпляров семейств и типов. Откройте RVT → «Виды и таблицы» → спецификацию →
«Сверочная ведомость по элементам» → «Построить сверочную ведомость».
Количество наблюдённых экземпляров считается без зависимости от успеха геометрии.

Это **частичная реконструкция для сверки**, не вычисленное тело Revit.
Сохранённые ячейки исходной таблицы показываются отдельно. Оформленные листы
и правила видимости видов этим механизмом не восстанавливаются.

## Порядок чтения и вычисления

1. Получить SHA-256 исходного RVT и нативный каталог спецификаций.
2. Прочитать определения параметров, затем текущие `FamilyInstance` и
   `FamilySymbol` через `native_document::extract`. В браузер передаются
   параметры, связи и адреса записей; объёмные графы геометрии не передаются.
3. Проверить совпадение SHA-256 каталога и параметров. Другой файл — отказ от
   соединения данных, даже при одинаковых ElementId.
4. Выбрать экземпляры по явному ID категории из цепочки «экземпляр → тип →
   семейство → категория». Не подбирать категорию или параметр по подписи.
5. Для поля использовать ID параметра и источник: экземпляр (`m_sourceType=0`)
   либо связанный тип (`1`). Поддержанный счётчик (`2`, `-1152353`) — одно
   наблюдение на уникальный экземпляр. Неизвестные источники остаются неподдержанными.
6. Прочитать также скрытые поля. Применить явные фильтры сверки до группировки;
   сохранить решение и исходное значение для каждого кандидата.
7. По умолчанию использовать сохранённые ключи сортировки и режим
   `m_bInstanceSchedule`. Можно переключиться на отдельные экземпляры или ID типа.
   Это интерпретация по профилю Увязки, требующая сверки с экспортом Revit.
8. Сохранить членов группы, значения, статусы, ограничения и происхождение.
   CSV содержит все поля/строки результата, JSON — также определения полей.

Неоднозначные ID исключаются из выборки с числом пропусков. Неизвестная
категория не превращается в нулевое количество. Противоречивые значения одного
параметра обозначаются конфликтом; разные значения нескольких экземпляров —
«Разные значения». Пустая строка, числовой ноль, пропуск и неподдержанное поле
имеют разные состояния. В группе с пропуском значение не считается полным.

## Типы значений и единицы

Основной источник — типизированные наборы параметров и слоты, разрешённые
по определениям из файла. Для пяти встроенных параметров есть отдельный
ограниченный профиль, основанный на закреплённом коде
[`partition_type_parameters.rs`](../integrations/rvt-rs/src/partition_type_parameters.rs)
(RE-77/RE-93, Apache-2.0). Это правило интерпретации Увязки, а не определение,
прочитанное из файла, и оно явно записывается в происхождение значения.

| ID | Слот | Единица / значение |
|---|---|---|
| -1001301 | Double | Ширина, исходные футы |
| -1001300 | Double | Высота, исходные футы |
| -1001405 | String | Марка типа |
| -1010103 | String | Описание |
| -1001206 | String | Огнестойкость, сохранённый текст |

Выбор по непустому слоту запрещён. Для остальных неизвестных типов хранения
сохраняются исходные слоты и статус «Не поддержано». Длины профиля показаны
в мм (`ft × 304.8`), CSV/JSON сохраняют исходные футы. Другие Double остаются
в исходных единицах без выдуманного обозначения. Сохранённые результаты формул
параметров не пересчитываются; формулы самих полей спецификации не исполняются.

## Отбор, группировка и контрольные суммы

В «Фильтры сверки и суммы» доступны равенство/неравенство, числовые сравнения,
содержит/не содержит, начало/конец строки и проверка прочитанного значения.
Поля выбираются по ID, включая скрытые. Условия соединены И, текст сравнивается
точно с учётом регистра. Порог должен иметь тот же тип и единицу; для размеров
можно ввести миллиметры, которые переводятся в исходные футы. Числа сравниваются
без допуска — это правило сверки, не воспроизведение внутренней точности Revit.

Для каждого экземпляра сохраняется `selection`: `pass`, `fail` или `unknown`,
условия и ячейки с доказательствами. Один подтверждённый `fail` исключает строку;
пропуск/конфликт/неподдержанное условие даёт `unknown`, если нет `fail`.
Непрочитанный параметр не означает отсутствующий параметр или пустое значение.
Ноль и пустая прочитанная строка проходят «Значение прочитано».

**Нативные фильтры RVT ещё не исполняются.** В проверенной локальной модели нет
примеров с заполненным `m_filterArr`. Числа перечислений Revit API нельзя считать
доказательством их бинарной кодировки в RVT. Если массив непустой или ссылка
не разрешена, все не исключённые кандидаты получают `unknown`, а не ложный
`pass`. Явные правила пользователя не отменяют это ограничение.

Сортировка использует `m_fieldId` и профиль `m_sortOrder: 0 → ascending,
1 → descending`; другие значения или потерянный ключ отключают её целиком.
Текст упорядочивается по строковому сравнению JavaScript; локализованный порядок
Revit не воспроизводится. ElementId не сортируются численно: ID уровня не его
отметка. При `m_bInstanceSchedule=false` строки объединяются по полному набору
прочитанных ключей. Неизвестные ключи остаются отдельными строками. Строки
`pass` и `unknown` никогда не объединяются. Флаги оформления групп сохраняются,
но заголовки и подытоги по ним не рисуются. Без ключей и при явном отключении
поэкземплярного режима формируется одна группа для каждого статуса отбора.

Контрольные суммы запрашиваются явно для выбранных полей и считаются **до**
группировки только по `pass`. Пропуск одного слагаемого блокирует сумму, разные
единицы дают конфликт; ElementId и текст не суммируются. Сумма без подтверждённых
строк — «Не прочитано», не ноль. Это не настроенные в Revit итоги спецификации.

JSON содержит полный журнал отбора, исключённые элементы, суммы, исходные
правила и ограничения. CSV содержит показанные строки, статусы отбора, правила
и источники ячеек. В UI журнал ограничен первыми 100 кандидатами; JSON полный.
Настройки сохраняются в localStorage по SHA-256 RVT и ID таблицы с версией
формата. Ошибка сохранения видна. Данные другой модели не подставляются.
Настройки и журнал пока не синхронизированы с SQLite/MCP.

Семантика расписаний сверена с документацией Autodesk:
[все фильтры должны выполняться, скрытые поля допустимы](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/a5dfec9f-1efd-b507-d079-eabcbf5032f8.htm),
[сортировка и поэкземплярный режим](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-DocumentPresent/files/GUID-C9407EBB-C78C-45DA-AB6D-D9F6B09274C5.htm).
Эти источники не документируют внутренний бинарный формат RVT.

## Ограничения и хранение

- Стадии, варианты, нативные фильтры, область видимости, связанные RVT,
  форматирование, проценты и итоги Revit не применяются. Показаны кандидаты
  доступной категории с явным статусом отбора. Итог всегда `partial`.
- Текущий набор охватывает экземпляры загружаемых семейств. Стены, помещения,
  материалы и другие классы нельзя считать полностью охваченными этой выборкой.
  Материальные, ключевые и вложенные спецификации не строятся.
- Просмотр ограничивает окно таблицы 50 строками × 8 полями; экспорт охватывает
  весь построенный результат. Геометрия не является условием попадания в выборку.
- Бюджет сериализованных записей параметров — 64 MiB. При превышении metadata
  записи опускается с явным статусом; нативные бюджеты обхода также действуют.
- Каталог с параметрами кешируется по SHA-256 и версии `native-document-v2` в
  IndexedDB. Ошибка извлечения не уничтожает каталог и не кешируется как успех.
  Исходные RVT в кеш не записываются. Синхронизации этого кеша с SQLite/MCP пока нет.

## Проверка 21.10.2026

На локальной модели Revit 2025 прочитаны 219 экземпляров и 334 типа;
прямой WASM-вызов занял около одной секунды. Для таблицы дверей получены
26 экземпляров, сгруппированных в 14 и 12 по двум типам. Прочитаны размеры
1800 × 2100 и 1000 × 2200 мм; другие отсутствующие значения не заполнены.
Это проверка чтения и вычисления по сохранённым данным, не сравнение
с результатом выполняющегося Revit API. Модель и её параметры не включены в Git.

В браузере проверены построение, группирование и источник размера. Выгруженный
CSV содержит две строки, 26 уникальных ID экземпляров, исходные футы, адреса
источников и ограничения.

После добавления правил проверен фильтр ширины > 1200 мм: 14 прошедших,
12 исключённых, 0 неопределённых. Контрольная сумма количества — 14;
JSON содержит 26 решений с исходными ячейками и доказательствами. Без фильтра
группировка по сохранённым ключам даёт две строки (14 и 12).
После перезагрузки страницы и повторного открытия того же RVT фильтр и выбранная
сумма восстановились; результат остался 14 прошедших / 12 исключённых.

Синтетические регрессии проверяют SHA-256, категории, связи типов, одинаковые
подписи разных параметров, пропуски, нули, конфликты, группирование, единицы,
формулы и CSV. Дополнительно проверяются скрытые ключи, сортировка, неопределённый
отбор, сочетание условий И, единицы порогов, суммы до группировки, переполнение
и изоляция сохранённых правил по SHA-256/ID таблицы.
Проходят 53 веб-теста; сборка TypeScript/Vite и проверка структуры пакета успешны.
