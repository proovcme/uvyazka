# Сверочная ведомость из RVT без Revit

Локальная смотрелка строит предварительные строки по нативным параметрам
экземпляров семейств, инженерных кривых и их типов. Откройте RVT → «Таблицы RVT» → спецификацию →
«Сверочная ведомость по элементам» → «Построить сверочную ведомость».
Количество наблюдённых экземпляров считается без зависимости от успеха геометрии.

В произвольной таблице фильтр категории также сохраняет экземпляры без
геометрии. Название нативной категории сопоставляется по её ID и явным связям
ElementId внутри одного SHA-256 источника. Разные названия одного ID дают
конфликт; непрочитанное название остаётся вопросом. Доказательства значения
и соответствия сохраняются в экспорте.

Каталог JSON выгружается без форматирующих отступов: данные и источники
сохраняются, а перенос в MCP не расходует лимит импорта на пробелы.
Для очень больших каталогов ограничение размера импорта по-прежнему действует.

Это **частичная реконструкция для сверки**, не вычисленное тело Revit.
Сохранённые ячейки исходной таблицы показываются отдельно. Оформленные листы
и правила видимости видов этим механизмом не восстанавливаются.

## Порядок чтения и вычисления

1. Получить SHA-256 исходного RVT и нативный каталог спецификаций.
2. Прочитать определения параметров, затем текущие `FamilyInstance` и
   `FamilySymbol`, поддержанные трубы, воздуховоды, гибкие кривые, лотки,
   короба, изоляцию и типы через `native_document::extract`. В браузер передаются
   параметры, связи и адреса записей; объёмные графы геометрии не передаются.
3. Проверить совпадение SHA-256 каталога и параметров. Другой файл — отказ от
   соединения данных, даже при одинаковых ElementId.
4. Для однокатегорийной таблицы выбрать экземпляры по явному ID категории из цепочки «экземпляр → тип →
   семейство → категория». `m_categoryId=-1` допускает многокатегорийную выборку.
   Не подбирать категорию или параметр по подписи. Для квалифицированных классов
   труб, воздуховодов, гибких кривых, изоляции, лотков и коробов используется
   отдельное соответствие встроенной категории. В доказательстве это проекция
   класса, а не прочитанное поле.
5. Для поля использовать ID параметра и источник: экземпляр (`m_sourceType=0`)
   с переходом к явно связанному типу при непрочитанном значении, либо только тип (`1`). Поддержанный счётчик (`2`, `-1152353`) — одно
   наблюдение на уникальный экземпляр. Неизвестные источники остаются неподдержанными.
6. Прочитать также скрытые поля. Применить поддержанные исходные фильтры RVT и дополнительные фильтры сверки совместно (И), до группировки;
   сохранить решение и исходное значение для каждого кандидата.
7. По умолчанию использовать сохранённые ключи сортировки и режим
   `m_bInstanceSchedule`. Можно переключиться на отдельные экземпляры или ID типа.
   Это интерпретация по профилю Увязки, требующая сверки с экспортом Revit.
8. Сохранить членов группы, значения, статусы, ограничения и происхождение.
   CSV содержит все поля/строки результата, JSON — также определения полей.

Неоднозначные ID исключаются из выборки с числом пропусков. Неизвестная
категория не превращается в нулевое количество. Противоречивые значения одного
параметра обозначаются конфликтом; разные значения нескольких экземпляров —
«Разные значения». Пустая строка, числовой ноль, пропуск и неподдержанное поле
имеют разные состояния. В группе с пропуском значение не считается полным.

## Типы значений и единицы

Основной источник — типизированные наборы параметров и слоты, разрешённые
по определениям из файла. Для пяти встроенных параметров есть отдельный
ограниченный профиль, основанный на закреплённом коде
[`partition_type_parameters.rs`](../integrations/rvt-rs/src/partition_type_parameters.rs)
(RE-77/RE-93, Apache-2.0). Это правило интерпретации Увязки, а не определение,
прочитанное из файла, и оно явно записывается в происхождение значения.

| ID | Слот | Единица / значение |
|---|---|---|
| -1001301 | Double | Ширина, исходные футы |
| -1001300 | Double | Высота, исходные футы |
| -1001405 | String | Марка типа |
| -1010103 | String | Описание |
| -1001206 | String | Огнестойкость, сохранённый текст |

Выбор по непустому слоту запрещён. Для остальных неизвестных типов хранения
сохраняются исходные слоты и статус «Не поддержано». Длины профиля показаны
в мм (`ft × 304.8`), CSV/JSON сохраняют исходные футы. Другие Double остаются
в исходных единицах без выдуманного обозначения. Сохранённые результаты формул
параметров не пересчитываются; формулы самих полей спецификации не исполняются.

## Отбор, группировка и контрольные суммы

В «Фильтры сверки и суммы» доступны равенство/неравенство, числовые сравнения,
содержит/не содержит, начало/конец строки и проверка прочитанного значения.
Поля выбираются по ID, включая скрытые. Условия соединены И, текст сравнивается
точно с учётом регистра. Порог должен иметь тот же тип и единицу; для размеров
можно ввести миллиметры, которые переводятся в исходные футы. Числа сравниваются
без допуска — это правило сверки, не воспроизведение внутренней точности Revit.

Для каждого экземпляра сохраняется `selection`: `pass`, `fail` или `unknown`,
условия и ячейки с доказательствами. Один подтверждённый `fail` исключает строку;
пропуск/конфликт/неподдержанное условие даёт `unknown`, если нет `fail`.
Непрочитанный параметр не означает отсутствующий параметр или пустое значение.
Ноль и пустая прочитанная строка проходят «Значение прочитано».

**Поддержанная часть нативных фильтров исполняется по профилю Увязки.**
Разрешаются явные ссылки `m_fieldId`, тип сохранённого порога и операции
равенства, числового сравнения, содержит, начало/конец строки и их отрицания.
Числа операций сверены с [официальным перечислением Autodesk](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/9b696f55-de40-8739-8cfb-decd51995cff.htm).
Это не доказательство всех вариантов бинарной кодировки RVT: профиль остаётся
`interpreted_requires_review`. Неизвестный код, потерянная ссылка, иной тип
порога, проверки наличия или глобального параметра сохраняют `unknown`.
Непрочитанные значения не проходят отрицательные условия автоматически.
Стадии, варианты, ссылки и видимость таблицы по-прежнему не применяются.

Сортировка использует `m_fieldId` и профиль `m_sortOrder: 0 → ascending,
1 → descending`; другие значения или потерянный ключ отключают её целиком.
Текст упорядочивается по строковому сравнению JavaScript; локализованный порядок
Revit не воспроизводится. ElementId не сортируются численно: ID уровня не его
отметка. При `m_bInstanceSchedule=false` строки объединяются по полному набору
прочитанных ключей. Неизвестные ключи остаются отдельными строками. Строки
`pass` и `unknown` никогда не объединяются. Флаги оформления групп сохраняются,
но заголовки и подытоги по ним не рисуются. Без ключей и при явном отключении
поэкземплярного режима формируется одна группа для каждого статуса отбора.

Контрольные суммы запрашиваются явно для выбранных полей и считаются **до**
группировки только по `pass`. Пропуск одного слагаемого блокирует сумму, разные
единицы дают конфликт; ElementId и текст не суммируются. Сумма без подтверждённых
строк — «Не прочитано», не ноль. Это не настроенные в Revit итоги спецификации.

JSON содержит полный журнал отбора, исключённые элементы, суммы, исходные
правила и ограничения. CSV содержит показанные строки, статусы отбора, правила
и источники ячеек. В UI журнал ограничен первыми 100 кандидатами; JSON полный.
Настройки сохраняются в localStorage по SHA-256 RVT и ID таблицы с версией
формата. Ошибка сохранения видна. Данные другой модели не подставляются.
Настройки и журнал пока не синхронизированы с SQLite/MCP.

Семантика расписаний сверена с документацией Autodesk:
[все фильтры должны выполняться, скрытые поля допустимы](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/a5dfec9f-1efd-b507-d079-eabcbf5032f8.htm),
[сортировка и поэкземплярный режим](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-DocumentPresent/files/GUID-C9407EBB-C78C-45DA-AB6D-D9F6B09274C5.htm).
Эти источники не документируют внутренний бинарный формат RVT.

## Ограничения и хранение

- Стадии, варианты, неподдержанные нативные фильтры, область видимости, связанные RVT,
  форматирование, проценты и итоги Revit не применяются. Показаны кандидаты
  доступной категории с явным статусом отбора. Итог всегда `partial`.
- Текущий набор охватывает экземпляры загружаемых семейств и поддержанные инженерные кривые. Стены, помещения,
  материалы и другие классы нельзя считать полностью охваченными этой выборкой.
  Материальные, ключевые и вложенные спецификации не строятся.
- Просмотр ограничивает окно таблицы 50 строками × 8 полями; экспорт охватывает
  весь построенный результат. Геометрия не является условием попадания в выборку.
- Бюджет сериализованных записей параметров — 128 MiB. При превышении metadata
  записи опускается с явным статусом; нативные бюджеты обхода также действуют.
- Каталог с параметрами кешируется по SHA-256 и версии `native-document-v5-workset-evidence` в
  IndexedDB. Ошибка извлечения не уничтожает каталог и не кешируется как успех.
  Исходные RVT в кеш не записываются. Каталог с исходными параметрами можно
  перенести в общую SQLite через импорт JSON в локальной смотрелке или
  import_rvt_catalog. Нативные снимки MCP открываются там же без нового извлечения.
  Пользовательские фильтры сверочной ведомости остаются отдельными настройками
  браузера и автоматически в SQLite не переносятся.

## Проверки и ограничения

Сверочная ведомость строится по извлечённым данным и явно заданным правилам.
Совпадение её итогов с работающим Revit API не подтверждено. Скорость и полнота
зависят от содержимого файла; универсальное восстановление спецификаций
по результату одного файла не заявляется.

Синтетические регрессии проверяют SHA-256, категории, связи типов, одинаковые
подписи разных параметров, пропуски, нули, конфликты, группирование, единицы,
формулы и CSV. Дополнительно проверяются скрытые ключи, сортировка, неопределённый
отбор, сочетание условий И, единицы порогов, суммы до группировки, переполнение
и изоляция сохранённых правил по SHA-256/ID таблицы.
Результаты текущих автоматических прогонов доступны в Actions репозитория.

Определения параметров передаются один раз в `schedule_data.summary.parameter_definitions`;
у владельца остаются ссылки `parameter_definitions_ids`, значения и адреса источников.
Старые каталоги с определениями у каждого владельца также читаются. Лимит
параметрической выдачи — 128 МиБ; превышение явно отмечается числом обрезанных
записей и частичным статусом. Кеш браузера обновлён, чтобы перечитать старую выборку.

В сохранённых ячейках пустой `m_text` при ссылке на параметр, формулу или
объединённое поле означает «Значение не прочитано». Он не подтверждает пустое
вычисленное значение. Заполненные исходные тексты и количества сохраняются;
непрочитанная ячейка не дополняется догадкой из похожей строки.

Рабочий набор читается из `Global/PartitionTable`: явный `identity.partition_id`
сопоставляется с живой пользовательской записью `m_type=0`. В таблице показывается
сохранённое имя; текстовый фильтр использует это имя, целочисленный — исходный ID.
Пути в таблице разделов сохраняются у ячейки. Неизвестный вариант таблицы,
удалённый набор или отсутствующий ID дают пропуск; имя по разделу или названию
элемента не угадывается.


## Представление человеку

Основной список содержит спецификации. Записи видов, листов, шаблонов и
размещений, для которых нет графического воспроизведения, доступны через
«Исходный каталог и технические данные»; в дереве они находятся в закрытом
разделе «Исходный каталог · без графического просмотра».

Исходные фильтры показаны понятными условиями перед построением таблицы,
включая скрытые поля. Неизвестное условие не подменяется отсутствием фильтра.
Служебные графы, JSON, журналы и подробные ограничения скрыты в закрытых
разделах. Таблица, количество, статус достоверности и пользовательские условия
остаются доступны сразу. В формах ГОСТ JSON-выгрузки находятся под
«Технические данные»; PDF и XLSX доступны в основной панели.


## Переход к модели и вопросы по строкам

У строки сверочной ведомости есть действие «Показать в модели». Соответствие
проверяется по SHA-256 исходного файла и явному Revit ElementId, включая
раздельные вхождения одного источника в сводной сцене. STEP ID, похожие имена
и другая ревизия не используются. Неоднозначный ID внутри одного вхождения
не связывается автоматически. Отсутствующая геометрия показана отдельно.
При переходе найденные элементы возвращаются из скрытых и камера приближается
к ним; поисковый запрос дерева сохраняется.

Карточка ячейки показывает состояние, файл и ID источников, способ получения
и причину непрочитанного значения. JSON появляется только при открытии
«Технических данных источника». Фильтр «Только строки с вопросами» оставляет
неопределённый отбор, пропуски, конфликты, неподдержанные и смешанные значения.
Это фильтр отображения: CSV, JSON и контрольные суммы используют весь состав
построенной ведомости. Нулевые значения и прочитанные пустые строки сами по
себе вопросом не считаются. Полнота исходного RVT этим фильтром не подтверждается.

Перелистывание и переключение отображения используют один построенный результат.
Изменение условий сверки сбрасывает его и пересчитывает отбор.

## Полнота чтения параметров

Каталог включает типы изоляции труб, воздуховодов и облицовки. Повторное
представление параметра в типизированном наборе и семейном слоте не удаляет
метаданные всего элемента: оба доказательства сохраняются. Различающиеся значения
или типы хранения дают конфликт; совпадающие значения не удваиваются.

Ссылка инженерного элемента на тип сохраняет числовой ID. Отдельная подпись
может показывать имя явно связанного типа; она не заменяет ID при отборе.
Для прямолинейных участков поддержана аналитическая длина по проверенной цепочке
«элемент → RbsCurveDriver → GLine». Это производное значение в исходных футах,
а не вычисленная Revit длина, не длина по сетке и не оценка гибкого участка.
Явно сохранённый параметр длины имеет приоритет. Неизвестная кривая остаётся
непрочитанной. Геометрические количества этим правилом не подтверждаются.

При группировке по исходным правилам поддержан `ScheduleFieldDisplayType.Totals`
для числовых полей. Складываются значения всех включённых экземпляров с одинаковыми
единицами. Непрочитанное слагаемое не становится нулём; смешанные единицы дают
конфликт. Ручная группировка по типу не включает исходные суммы автоматически.
Минимумы, максимумы и особые итоги сборок этим правилом не восстанавливаются.

Отсутствующее сохранённое значение отличено от ошибки чтения. Ни то ни другое
не заменяется нулём и не объявляется вычисленной пустой ячейкой Revit.
Каталог документов и параметров допускает до миллиона значений на запись;
пределы контейнеров, объектов, потоков и выходного объёма сохраняются. Глобальные
лимиты чтения 3D не увеличены: для тяжёлых записей остаётся явный частичный охват.

## Общее ядро таблиц для MCP и GUI

Веб-интерфейс и MCP используют одни реализации отбора, группировки и итогов:
`model-specification.ts`, `rvt-schedule.ts`, `gost-specification.ts` и
`specification-xlsx.ts`. Сборка `npm --prefix web run build:tables` создаёт
локальный модуль для Python. Дополнение `uvyazka[tables]` запускает его во
встроенном V8; Node.js и API модели при работе не нужны. Ввод передаётся как
данные JSON; пользовательские скрипты не исполняются.

Для зарегистрированного RVT:

1. `prepare_model_tables(project_id, doc_id, request_id)` прямо читает
   параметры экземпляров/типов и определения спецификаций. Экспорт каталога
   из браузера для этого не требуется. Возвращает `extraction_id`.
2. `get_model_table_schema` выдаёт поля с точными ID, привязанные источники,
   исходное определение таблицы и неподтверждённое предложение ГОСТ.
   Поля можно искать через `query`, страницы — через `next_offset`.
3. `build_model_table` сохраняет результат в SQLite проекта. Режим
   `parameters` использует явное `definition`; `native_schedule` — точный
   `element_id` исходной спецификации; `gost` — её явно выбранные привязки.
4. `read_model_table` читает строки, отбор, вопросы и итоги. Большие ячейки
   читаются через `section=value`, `json_path` и символьное продолжение.
5. `export_model_table` сохраняет JSON, CSV или XLSX для ГОСТ вместе с
   манифестом происхождения. Новый экспорт не перезаписывает предыдущий.

Снимок таблицы включает версию ядра, каталога, ID сцены и определение.
Один `request_id` нельзя использовать для другой таблицы. Вызов после
обновления ядра требует нового `request_id`; прежние результаты сохраняются.
Одинаковый код не является независимой инженерной проверкой самого алгоритма.

Нативное чтение использует компактную проекцию браузера: определения параметров
не дублируются в каждом владельце, имена рабочих наборов сохраняются отдельно.
Выход читается страницами с проверкой точного продолжения и конечного количества.
Это снимает общий прежний обрыв выгрузки, но не снимает ограничения читателя:
отдельная запись свыше 32 МиБ остаётся явно частичной. Предыдущие снимки с
обрезанными данными не переименовываются в полные.

Категория без сетки определяется по прочитанному BuiltInCategory ID. Если
собственная подпись не прочитана, используется явно отмеченный английский
справочник закреплённого rvt-rs. Неизвестный ID остаётся неизвестным;
конфликт исходных подписей не заменяется справочником. ГОСТ допускает нативные
записи физического экземпляра с подтверждённой категорией без требования сетки.
Текстовое сходство имени не подтверждает категорию или количество.

Для новой таблицы `definition.columns[].unit` задаёт единицу вывода. В GUI
это выбор единиц рядом с итогом поля. Преобразуются только подтверждённые
единицы совместимой размерности; исходные величины и коэффициент сохраняются
в доказательствах. Порог фильтра остаётся в явно заданной исходной единице.
Числу с единицей `native` нельзя назначить метры или килограммы по подписи.

Синтетические тесты проверяют совпадение веб-модуля и встроенной сборки,
неизвестные значения, повторные запросы, изоляцию проектов и экспорт.
Частные исходники и результаты проверок не входят в репозиторий. Успешная
сборка строк не подтверждает все правила видимости, формулы, связанные модели
и вычисленные итоги исходной спецификации. Сравнение с авторским экспортом
Revit остаётся отдельной приёмочной проверкой.
