# Листы, таблицы и независимое чтение

Буквальный структурный слой авточиталки хранится в **той же SQLite проекта**,
что источники и наблюдения. Новый приём папки/ZIP выполняет этап `structuring`.
Для ранее принятых проектов есть кнопка «Собрать структуру» в разделе
«Листы и таблицы» и MCP `build_project_structure`.

Человек и модель продолжают работу по project_id, table_id и cell_id. Для
этого не нужны API генерации, отдельный чат или эмбеддинги. Модель также
может самостоятельно читать оригиналы.

## Поддержка источников

| Источник | Сохранённая структура | Ограничения |
|---|---|---|
| PDF | Физические страницы, поворот/crop, таблицы, текст и bbox ячеек | Сканы требуют OCR/визуального чтения; тяжёлая векторная страница может быть пропущена с предупреждением |
| XLSX/XLSM | Листы, A1-адреса, типы, объединения, формулы и кеш результатов, форматы, скрытые строки/столбцы, области печати, разрывы, определения Excel Tables | Формулы, VBA и внешние связи не исполняются; отсутствие кеша видно отдельно |
| XLS | Листы, адреса, типы, форматы, объединения, сохранённые значения | xlrd не раскрывает выражения формул; значение может быть сохранённым результатом. Пустота/отсутствие могут быть неразличимы; чтение явно частичное |
| DOCX | Основная XML-часть, колонтитулы, порядок блоков, таблицы и вложенные таблицы, объединения, флаг повторной шапки, XML-пути | Логические части не считаются физическими страницами; сложные конструкции требуют проверки оригинала |
| CSV/TSV | Строки/столбцы, буквальные значения, пустые позиции | Печатных листов нет; смысл шапки предварительный |

Старый бинарный **DOC не поддержан**. TXT/Markdown доступны через текстовый
поиск, RVT — через нативный каталог. В PDF напечатанный номер листа остаётся
неизвестным, пока его не установили по источнику. Виды и собственные масштабы
регистрируются инструментами [измерений](MEASUREMENTS.md); автоматического
распознавания всех видов в новом каталоге нет.

## Версии и интерпретация

`structure_versions` фиксирует doc_id, SHA-256, адаптер/библиотеку и позицию
обхода; `structure_units` — страницы/части; `structure_tables` — карточки и
поисковый текст; `structure_rows` — исходные ячейки. Нативная Excel Table
остаётся в метаданных, буквальные ячейки представлены одной сеткой worksheet.
Таблицы с одинаковыми заголовками не склеиваются.

Пустота, отсутствие, продолжение объединения, ноль, прочерк, формула и
неразобранная пустота различаются. Продолжение объединения не повторяет
количество. Формула и её кеш — отдельные поля. Инструкции документов не
исполняются. Предупреждения библиотек и исходные определения печати сохраняются.

Цепочки заголовков с cell_id и пять типов по словам шапки — предварительные
гипотезы: экспликация, спецификация, состав проекта, объёмы, показатели.
Это **не полные профили СПДС и не нормоконтроль по ГОСТ**. Единицы, область,
итоги и инженерный смысл проверяет человек/модель.

После изменения SHA или адаптера каталог показывает текущую зарегистрированную
версию. Старые снимки и чтения сохраняются, исторический table_id возвращается
с признаком устаревания. Чтение проверяет реальный SHA по умолчанию, но не
парсит источник заново; навигация проверяет только зарегистрированную версию.

## Операции UI и MCP

1. Принять проект или выбрать имеющийся project_id. Прямая работа с папкой
   требует предварительного сканирования зарегистрированных источников.
2. `get_project_structure(kind="documents")` — состояние документов.
3. `build_project_structure(unit_limit=5, document_limit=3)` — продолжить обход
   до `coverage.pending_documents=0`. Отсутствие прогресса требует разбора причины.
4. `get_project_structure(kind="sheets"|"tables", query=..., offset=...)` —
   навигация; поиск таблиц включает исходный текст ячеек.
5. `read_structure_table(table_id, offset, limit, column_offset, column_limit)` —
   окна по умолчанию 40 × 20, максимум 100 × 50. Продолжать оба направления.
6. `record_structure_review` — чтение человека/модели рядом с результатом кода.
   После интерпретации показателя отдельно используется `record_observations`.

HTTP `/api/structure/catalog`, `/table`, `/build`, `/review` вызывает те же
методы. Запись требует loopback Host, допустимый Origin и токен сессии.
UI показывает обработку порциями, остановку между порциями, поиск, копируемые
значения/свойства и форму чтения. Полной панели истории чтений пока нет.

Ошибка адаптера завершает конкретный документ статусом failed и не блокирует
остальные. После исправления причины `retry_failed=true` повторяет одну порцию;
дальнейшие вызовы снова с false. В UI отдельная кнопка повторяет до десяти
неудачных файлов. Failed/partial/unsupported — покрытие извлечения, не замечания
к проектным решениям. Текстовая сводка остаётся отдельным слоем.

## Независимое чтение

`structure_reviews` хранит неизменяемую историю: источник, адрес, reader,
метод, текст/состояние, причину, ревизию и request_id. reader=model|human.
Методы visual_original/native_source — заявленное чтение оригинала;
инструмент не может доказать независимость. cached_extraction явно не независим.
Чтение таблицы парсера не следует выдавать за второе извлечение.

Исправление требует expected_revision и причины. request_id повторяется
только для идентичного запроса. Ячейка возвращает последние чтения обоих
участников и номера ревизий; предыдущие записи остаются в SQLite.

Сравнение различает буквальное/числовое совпадение, расхождение чтения,
вопрос, нечитаемость и устаревание. Числовая эквивалентность ограничена простыми
десятичными скалярами, без преобразования единиц и области измерения.
Совпадение двух чтений **не принимает инженерное значение**.

## Границы и проверка

Источник/распакованный офисный контейнер — до 64 MiB; сетка — 20000 строк,
512 столбцов, 300000 ячеек. XLSX/XLSM — до 300000 сериализованных ячеек книги
перед загрузкой объектов. Это границы данного адаптера, не RVT/DWG-вьювера.
Превышение явно отражается в диагностике. Порция — до десяти единиц каждого
из максимум десяти документов. Ответ чтения ограничен 1 MiB: большие значения
требуют меньшего окна.

Синтетические проверки: объединения, нули/типы/пустота, формулы без кеша,
XLS, вложенные таблицы Word и колонтитулы, PDF-поворот/crop/сканы, пагинация,
версии, две линии чтения, идемпотентность, HTTP-защита, автоматический приём,
официальный MCP stdio после перезапуска. HappyDOM проверяет интерфейс и остановку
записи при смене проекта. Это не визуальная приёмка браузером и не полный
инженерный аудит произвольного проекта.
