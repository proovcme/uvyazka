# Данные проекта и сохранение чисел

## Выбор хранилища

SQLite — основная локальная база и журнал происхождения. Документы/изображения хранить отдельно, в базе — идентификаторы, хеши и адреса. FTS5 хранит индекс текста. Необязательный локальный векторный поиск дополняет его без подмены точных сопоставлений. Parquet и PostgreSQL рассматриваются как варианты дальнейшего развития; в текущую реализацию они не включены.

## Слои

1. Неизменяемые оригиналы и их версии.
2. Страницы/листы/области/ячейки, извлечённый текст, числовые токены с контекстом.
3. Сущности и именованные свойства, единицы и основания пересчёта.
4. Производные количества, расчёты, сопоставления и решения.
5. Краткий паспорт, выборки для модели, график и документы выпуска.

Сохранение всех числовых токенов обеспечивает обнаружение потенциальных данных. Для инженерной базы необходимо определить смысл каждого числа. Число без понятного свойства хранить как неразобранное наблюдение с источником, а не придумывать ему смысл.

## Категории и важные различия

| Категория | Что хранить отдельно |
|---|---|
| Объект и участок | Площадь участка по правовому документу и охват ГП; этапы; пятно застройки; общая/полезная/расчётная площадь; строительный объём; метод подсчёта |
| Помещения и экспликации | Номер и внутренний ID помещения, назначение, площадь, этаж/уровень, группа помещений, категория, источники разных разделов. Номер помещения уникален внутри объекта/этажа/версии, не во всей папке |
| Высотность и этажность | Этажность и количество этажей; надземные/подземные/технические; антресоль; относительные отметки; абсолютный ноль; геометрическая/пожарно-техническая высота; верх кровли/парапета. Не вычислять этажность простым делением высоты |
| Конструкции | Марка, материал/класс, исполнение, размеры, масса единицы, число экземпляров, объём в одном/всех элементах, армирование, зона и стадия монтажа |
| Системы и оборудование | ID/марка/модель; основное/резервное; единичная и групповая нагрузка; установленная, присоединённая, расчётная и допустимая мощность; холод/тепло, расходы и давления; режим одновременности; точки подключения |
| ТУ | Организация и реквизиты; выдача/срок действия; точка и граница ответственности; разрешённые параметры; требования к мероприятиям и срокам; сравниваемая проектная потребность с тем же режимом |
| Количества | Геометрия, работа, ресурс, поставка, резерв/потери, повторное использование, демонтаж/монтаж/восстановление, нетто/брутто, существующее/новое |
| Финансы | Вид документа и иерархия: ЛСР/ОСР/ССР/договор/платёж; цена и валюта; базисный/текущий уровень; дата/регион/индекс; НДС; единица и стоимость единицы; бюджет/факт/обязательства; исходный и пересчитанный курс. Не суммировать ОСР с входящими ЛСР |
| Сроки | Календарь, рабочие/календарные длительности, ресурсы, поставки, директивные/расчётные/фактические даты, допуски к работе, степень готовности и метод измерения |

## Универсальная запись

`observation_id; entity_id; property_code; raw_value; decimal_value; unit_code; unit_scale; quantity_basis; role; scenario; spatial_scope; source_revision_id; locator; extraction_method; confidence_evidence; verification_status`

Для денег и точных количеств использовать десятичную арифметику. В SQLite исходное точное число можно хранить строкой decimal; сравнение и финансовые итоги выполнять через Decimal. Не терять точность при автоматическом приведении всего к float. Диапазоны, отрицательные корректировки и составные показатели хранить по их типу.

Производная запись содержит формулу/версию правила, входные observation_id, правила единиц и округления, автора решения, дату и перечень зависящих outputs. Разные источники одного свойства сохраняются как разные observations; принятие одной версии не удаляет альтернативу.

## Полнота и обновление

Считать по разделу: файлов/страниц получено; прочитано парсером; требует OCR; числовых наблюдений найдено/классифицировано; позиций сопоставлено/без пары; вопросов открыто; проверок устарело. Указывать знаменатель: «сверено 25 марок из 40», а не «точность 98%» без эталонной выборки.

Идентичный хеш не пересчитывать. Новый хеш - новая версия. Изменённые факты помечают зависимые расчёты и документы `stale`. Изменение версии OCR/парсера требует отдельного ключа кеша. Изменение модели embeddings требует пересоздания только соответствующего индекса, а не повторного инженерного чтения проекта. Обновление нормативной базы отслеживается отдельно от изменений файлов.

Фактическая SQLite хранит документы, версии извлечения, наблюдения с историей, сверки, граф сущностей, измерения, разборы и очередь выбранных проверок. Есть адресный OCR, планировщик и необязательный смысловой индекс. Универсальная инженерная схема всех свойств, подтверждение полноты проекта и автоматический выпуск ПОС/ППР ещё не реализованы. Счётчики выбранной очереди не подтверждают проверку всех строк проекта. Универсальная запись выше — ориентир для организации данных; фактические поля описаны в документации ядра.
