# Измерения и продолжение работы между сессиями

В локальном браузере есть рабочее место `/measurements/?project=<project_id>`.
Оно пишет в ту же базу. Перед изменением повторно читай текущие ревизии:
пользователь мог вручную исправить калибровку или контур. `created_by=user`
обозначает ручной канал записи, не инженерное утверждение.
Сохраняй причину своего исправления и не перезаписывай устаревшую ревизию.

Применять к обмерам PDF. Код предоставляет операции, модель определяет виды,
смысл границ, контрольные размеры и пригодность метода.

## Сначала восстановить состояние

1. Выбрать `project_id`. Через `get_drawing_measurements` прочитать виды,
   затем калибровки и измерения нужного вида. Использовать `next_offset`.
2. Проверить `stale_reasons` и статус. Число с прежним масштабом остаётся
   доступным в истории, но не является текущим результатом.
3. Новый документ зарегистрировать обычным приёмом проекта; получить DOC-ID
   и SHA из `find_documents`. Работать с конкретной редакцией, не с именем файла.

## Лист → вид → калибровка → измерение

1. Вызвать `inspect_measurement_sheet`: размеры страницы, поворот исходного PDF,
   слова с координатами (`section=text`) или векторные примитивы (`section=vectors`).
   Область выбирает пересекающиеся пути, а не обрезает их геометрию;
   линии не объявляются стенами. Пустой текст не доказывает пустоту листа; OCR здесь нет.
2. Вызвать `render_drawing_measurements` без вида: осмотреть весь лист.
   Найти отдельные планы, разрезы, узлы, таблицы и ссылки между ними.
3. Сохранить каждый измеряемый вид через `save_drawing_view`.
   Указать `id`, `doc_id`, `sha256`, `page_number`, `name`, `kind`,
   `region=[x0,y0,x1,y1]`, `measurement_basis`, `reason`.
   `sheet_label` хранит печатный номер листа отдельно от PDF-страницы.
   Для новой записи `expected_revision=0`, для исправления — текущая версия.
4. Выбрать контрольный размер именно этого вида. Вызвать
   `calibrate_drawing_view` с двумя точками, действительной длиной `length_m`
   и `basis`, объясняющим прочтение размера. Длину в мм сначала перевести в метры.
   Для первой калибровки `expected_calibration_revision=0`.
5. Вызвать `measure_drawing_view` с версией вида и калибровки, пакетом 1–40
   измерений. Для каждого задать `id`, `name`, `kind=length|area`,
   `points`, смысловую `basis`, `reason`; при необходимости `entity_ref`.
   Результат включает исходные вершины, числовое значение, единицу и версии.
6. Вызвать `render_drawing_measurements` с видом и ID измерений.
   Проверить наложенный контур: какая граница взята, нет ли пропущенных выступов,
   отверстий, соседнего вида, условной линии или двойного обхода.
7. Сохранить результат проверки через `review_drawing_measurements`:
   `id`, `expected_revision`, `verdict=geometry_checked|question`, `note`.
   Это заявление агента о проверке, не инженерное утверждение человеком.

Каждую завершённую операцию сохранять сразу и проверять ответ инструмента.
Идентификатор `request_id` повторять только при повторе **тех же аргументов**.
Ошибка внутри пакета откатывает весь пакет. Для исправления записи нужны её
ID, текущая версия и причина; исправление добавляет версию, а не стирает историю.
Не обещать сохранение на основании текста в чате.

## Координаты и масштабы

- Все точки — `pdf_unrotated_top_left_points`: начало сверху слева в рамке,
  возвращённой инспектором после снятия PDF-поворота. Это не пиксели снимка.
- Рендер возвращает `pixel_origin_page_points` и `pixels_per_point`.
  Для точки снимка: `page_point = pixel / pixels_per_point + origin`.
  Использовать параметры конкретного снимка, а не экранный масштаб интерфейса.
- `orientation_degrees` — описанное моделью направление вида; оно не меняет
  координаты измерений. Поворот сам по себе не меняет длину или площадь.
- У каждого вида собственная калибровка. Общая подпись масштаба на листе
  не доказывает масштаб узла или отдельного фрагмента.
- Текущий инструмент поддерживает только равномерный плоский масштаб.
  Разрыв изображения, перспектива, деформированный скан и разные масштабы по
  осям требуют другого метода. Не калибровать весь такой вид по одному размеру.
- Напечатанный размер, измеренная длина и расчётное значение — разные записи.
  Число из расчёта не записывать через `record_observations` как цитату из PDF.

## После исправления

Изменение контрольного размера создаёт новую калибровку и делает зависимые
измерения устаревшими при чтении. Прочитать список; передать нужные
`{id,expected_revision}` в `recalculate_drawing_measurements` с текущими
версиями и причиной. Проверить новый рендер. Прежняя отметка проверки
сбрасывается, прежние числа остаются в истории.

При изменении границы вида или хеша PDF автоматический перенос контуров
запрещён инструментом: осмотреть новый источник, исправить вид, откалибровать
и сохранить заново проверенную геометрию как следующую версию измерения.
Историю читать через `history=true`, ограничивая её `record_id`.

## Границы первого выпуска

Ломаные и простые полигоны без отверстий. Самопересечения и выход за
прямоугольную область вида отклоняются. Простая форма ещё не означает
правильную интерпретацию: это проверяет модель по изображению.
Кривые, вычеты, объём, автоматическое распознавание видов, утверждение человеком
и общая сумма нескольких перекрывающихся контуров здесь не реализованы.
Повторное изображение объекта на разрезе не считать новым объектом.

Счётчики показывают сохранённые записи. Они не подтверждают, что все виды листа
обнаружены и все количества проекта проверены. Не переносить измерения в ВОР,
смету или график без установления сущности, базы подсчёта и проверки дублей.
